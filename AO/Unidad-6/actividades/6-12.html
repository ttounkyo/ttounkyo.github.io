Las preguntas

Una buena respuesta explica la idea con frases sencillas y la acompaña de un ejemplo tuyo (del instituto, de una tienda, de una aplicación que uses…). No hace falta que sea tan larga como la respuesta modelo.

  1. Base de datos, tabla, columna y fila

    Define por separado estos cuatro conceptos: base de datos, tabla, columna y fila.

    Ver la respuesta modelo
    • Base de datos: un conjunto de datos relacionados entre sí, organizados y guardados de forma que se puedan buscar, añadir y cambiar fácilmente. Ejemplo: la base de datos del instituto, con los alumnos, los grupos y las notas.
    • Tabla: la estructura donde se guardan los datos de un mismo tipo de cosa, organizados en filas y columnas. Ejemplo: la tabla Alumnos.
    • Columna (o campo): un dato concreto que se guarda de todos los elementos de la tabla. Tiene un nombre y un tipo. Ejemplo: la columna nombre, de tipo texto.
    • Fila (o registro): todos los datos de un elemento concreto. Ejemplo: la fila de una alumna, con su DNI, su nombre y su grupo.

  2. Características de una base de datos

    ¿Qué características tiene una base de datos?

    Ver la respuesta modelo
    • Datos organizados e integrados: toda la información está en un solo sitio y ordenada en tablas relacionadas.
    • Poca redundancia: cada dato se guarda, si es posible, una sola vez.
    • Integridad: hay reglas (tipos de datos, claves, restricciones) que impiden guardar datos incorrectos, como un precio con letras o un DNI repetido.
    • Se describe a sí misma: además de los datos, guarda cómo son las tablas y sus columnas (los metadatos).
    • Compartida: la pueden usar muchas personas y programas a la vez.
    • Segura: cada usuario solo puede ver o cambiar lo que tiene permitido.
    • Se maneja con un SGBD y un lenguaje (SQL) que permite ordenar, buscar, relacionar y calcular.

  3. Ventajas de una base de datos

    ¿Qué ventajas tiene usar una base de datos en lugar de guardar la información en archivos sueltos u hojas de cálculo?

    Ver la respuesta modelo
    • Menos datos repetidos y, por tanto, menos contradicciones (el mismo cliente con dos direcciones distintas).
    • Datos fiables: el SGBD comprueba los tipos y las claves antes de guardar.
    • Varios usuarios a la vez sin estropear los datos: el SGBD controla que dos personas no cambien lo mismo al mismo tiempo.
    • Seguridad: permisos distintos para cada usuario (uno solo puede leer, otro puede cambiar).
    • Vistas distintas: cada usuario puede ver solo la parte que le interesa.
    • Independencia: se puede cambiar la estructura de las tablas sin tener que rehacer todos los programas que las usan.
    • Copias de seguridad y recuperación si algo falla.
    • Consultas potentes: con una sola consulta SQL se cruzan datos de varias tablas.

  4. Clasificación de los SGBD

    ¿Qué es un SGBD? ¿Cómo se pueden clasificar?

    Ver la respuesta modelo

    Un SGBD (sistema gestor de bases de datos) es el programa que crea y mantiene las bases de datos y controla quién accede a ellas y cómo. Ejemplos: MySQL, MariaDB, PostgreSQL, Oracle, SQL Server o Access.

    • Según el modelo de datos: relacionales (los datos en tablas relacionadas; son los más usados, como MySQL), jerárquicos y en red (más antiguos), y orientados a objetos.
    • Según el número de usuarios: monousuario (un usuario cada vez) o multiusuario (muchos a la vez).
    • Según dónde están los datos: centralizados (todo en un mismo ordenador o servidor) o distribuidos (repartidos entre varios ordenadores conectados en red).

  5. Tipos de datos

    ¿Qué es un tipo de dato? Explica los que conozcas.

    Ver la respuesta modelo

    El tipo de dato de una columna dice qué clase de valores puede guardar: números, texto, fechas… Así el SGBD rechaza los valores que no encajan, sabe cuánto ocupan y qué operaciones puede hacer con ellos (sumar números, ordenar fechas…).

    Familia Tipos de MySQL Ejemplo
    Números enteros INT, SMALLINT, BIGINT Número de habitantes
    Números con decimales DECIMAL(p,s) (exacto), FLOAT, DOUBLE Precio: DECIMAL(8,2)
    Texto CHAR(n) (largo fijo), VARCHAR(n) (largo variable), TEXT (textos largos) DNI: CHAR(9); nombre: VARCHAR(50)
    Fecha y hora DATE, TIME, DATETIME, TIMESTAMP Fecha de nacimiento: DATE
    Sí o no BOOLEAN (guarda 1 o 0) ¿Tiene proyector?
    Binarios BLOB Una imagen o un archivo

    PRIMARY KEY, UNIQUE o NOT NULL no son tipos de datos: son restricciones, reglas que se añaden a una columna además de su tipo.

  6. El diagrama entidad-relación

    ¿Qué es un diagrama entidad-relación y para qué sirve?

    Ver la respuesta modelo

    Es un dibujo que representa el diseño de una base de datos antes de crearla: qué cosas hay que guardar (entidades), qué datos se guardan de cada una (atributos) y cómo se relacionan entre ellas (relaciones). Lo propuso Peter Chen en 1976; en su notación, las entidades son rectángulos, las relaciones rombos y los atributos elipses.

    Sirve para pensar el diseño sin preocuparse todavía del programa, para hablarlo con quien encarga la base de datos y como plano para crear después las tablas.

  7. Los tres conceptos del modelo E-R

    El modelo entidad-relación se basa en tres conceptos. ¿Cuáles son? Defínelos.

    Ver la respuesta modelo
    • Entidad: una cosa, persona o idea de la que queremos guardar datos (ALUMNO, LIBRO). Se dibuja con un rectángulo.
    • Atributo: una característica de una entidad o de una relación (el nombre del alumno, el título del libro). Se dibuja con una elipse.
    • Relación: la asociación entre dos o más entidades (un alumno toma prestado un libro). Se dibuja con un rombo, normalmente con un verbo.

  8. Entidades y tipos de atributos

    ¿Qué es una entidad? ¿Y un atributo? ¿Qué es un atributo derivado? ¿Qué significa que un atributo es univaluado o multivaluado?

    Ver la respuesta modelo
    • Entidad: algo del mundo real (una persona, un objeto, un lugar) o una idea (un préstamo, una matrícula) que se distingue de los demás y del que queremos guardar datos. Ejemplo: cada alumno del instituto es un ejemplar de la entidad ALUMNO.
    • Atributo: cada uno de los datos que describen una entidad. Ejemplo: DNI, nombre y fecha de nacimiento de ALUMNO.
    • Atributo derivado: el que se puede calcular a partir de otros, así que no hace falta guardarlo. Ejemplo: la edad, que sale de la fecha de nacimiento. Se dibuja con una elipse discontinua.
    • Atributo univaluado: tiene un solo valor para cada ejemplar. Ejemplo: el DNI de un alumno.
    • Atributo multivaluado: puede tener varios valores para el mismo ejemplar. Ejemplo: los teléfonos de un alumno. Se dibuja con una elipse doble y, al pasar a tablas, se guarda en una tabla aparte.

  9. Las claves

    Explica todo lo que sepas de las claves.

    Ver la respuesta modelo
    • Clave primaria: el atributo (o atributos) que identifica cada fila de forma única. No se puede repetir ni quedar vacía. Ejemplo: el DNI en la tabla de alumnos. En el diagrama E-R y en el esquema se escribe subrayada.
    • Claves candidatas: todos los atributos que podrían servir de clave primaria. Un alumno se puede identificar por su DNI, por su número de expediente o por su correo del instituto. Se elige una como clave primaria; las demás quedan como claves alternativas (en SQL se les pone UNIQUE).
    • Clave compuesta: la formada por varias columnas, cuando ninguna sola basta. Ejemplo: en la tabla de notas, DNI del alumno + código del módulo.
    • Clave ajena (o foránea, foreign key): una columna que guarda el valor de la clave primaria de otra tabla para relacionarlas. Ejemplo: la columna Fabricante de Articulos, que guarda el código de un fabricante. El SGBD no deja guardar un valor que no exista en la otra tabla (integridad referencial).

  10. Las relaciones y sus tipos

    ¿Qué son las relaciones? ¿Qué tipos de relaciones conoces? Explica sus características.

    Ver la respuesta modelo

    Una relación es la asociación entre entidades: un alumno cursa módulos, un ordenador está en un aula. Su cardinalidad dice cuántos ejemplares de una entidad se pueden asociar con uno de la otra:

    Tipo Qué significa Ejemplo En tablas
    1:1 Cada uno se asocia con uno solo del otro lado. Un departamento tiene un director y un empleado dirige un solo departamento. La clave de una tabla va como clave ajena a la otra.
    1:N Uno de un lado se asocia con muchos del otro, pero no al revés. Un fabricante hace muchos artículos; cada artículo es de un fabricante. La clave del lado 1 va como clave ajena a la tabla del lado N.
    N:M Muchos se asocian con muchos. Un alumno cursa muchos módulos y un módulo lo cursan muchos alumnos. Se crea una tabla nueva con las claves de las dos.

    Según cuántas entidades une, una relación puede ser binaria (dos entidades, la más habitual), ternaria (tres) o reflexiva (una entidad consigo misma: un empleado supervisa a otros empleados).

  11. Explica este diagrama

    Observa el diagrama y explica todo lo que sepas de él: entidades, atributos, claves, la relación, sus atributos y su cardinalidad. Si te atreves, escribe también las tablas que saldrían.

    Ver la respuesta modelo
    • Hay tres entidades: PROVEEDOR, PIEZA y PROYECTO.
    • Atributos y claves: PROVEEDOR tiene id (clave primaria, por eso está subrayado), nombre y dirección. PIEZA tiene id (clave), nombre y color. PROYECTO tiene código (clave), nombre y presupuesto. Todos son univaluados (elipse simple).
    • Hay una sola relación, «suministra», que une las tres entidades a la vez: es una relación ternaria. Cada suministro dice qué proveedor entrega qué pieza a qué proyecto.
    • La relación tiene dos atributos propios: cantidad y fecha. No son de ninguna entidad, sino de cada suministro.
    • La cardinalidad es M, N y P: muchos en los tres lados. Un proveedor puede suministrar muchas piezas a muchos proyectos, una pieza la pueden suministrar muchos proveedores a muchos proyectos, y un proyecto recibe muchas piezas de muchos proveedores.

    Al pasarlo a tablas, cada entidad es una tabla y la relación, como es de muchos a muchos, se convierte en una tabla nueva con las tres claves y los atributos de la relación:

    PROVEEDOR (id, nombre, direccion)

    PIEZA (id, nombre, color)

    PROYECTO (codigo, nombre, presupuesto)

    SUMINISTRA (id_proveedor, id_pieza, codigo_proyecto, cantidad, fecha)

    Si el mismo proveedor pudiera entregar la misma pieza al mismo proyecto varias veces, habría que añadir la fecha a la clave de SUMINISTRA.

Unidad 6. SQL: crear y consultar bases de datos

La parte de SQL tiene 5 actividades guiadas y 2 de repaso. Ver las actividades

Antes de empezar, conviene haber leído la teoría de diseño de bases de datos: aquí se da por sabido qué son una tabla, una clave primaria y una clave ajena.

1. Qué es SQL y cómo vas a practicar

SQL (Structured Query Language, lenguaje de consulta estructurado) es el lenguaje con el que se habla con un sistema gestor de bases de datos (SGBD) como MySQL, MariaDB, PostgreSQL, SQLite, Oracle o SQL Server. Con SQL creas las tablas, guardas datos, los cambias y, sobre todo, le haces preguntas a la base de datos: «¿qué artículos cuestan menos de 20 €?».

Cada orden de SQL se llama sentencia, y se parece bastante al inglés: SELECT Nombre FROM Articulos WHERE Precio < 20; se lee «selecciona el nombre de los artículos donde el precio es menor que 20». Casi todo lo que vas a aprender sirve en cualquier SGBD. En clase usamos MySQL, que es de los más usados en páginas web.

Los tipos de sentencias

Las sentencias de SQL se suelen agrupar según para qué sirven:

Grupo Para qué sirve Órdenes
DDL (Data Definition Language, definición de datos) Crear, cambiar y borrar la estructura: bases de datos y tablas. CREATE, ALTER, DROP, TRUNCATE
DML (Data Manipulation Language, manipulación de datos) Añadir, cambiar y borrar filas. INSERT, UPDATE, DELETE
DQL (Data Query Language, consulta de datos) Consultar los datos. SELECT
DCL (Data Control Language, control de datos) Dar o quitar permisos a los usuarios. GRANT, REVOKE

Muchos libros (y el manual de clase) meten SELECT dentro del DML y hablan solo de tres grupos. Las dos formas son correctas: lo importante es saber qué hace cada orden. Las de DCL no las vas a usar en esta unidad.

Reglas para escribir SQL

  • Cada sentencia termina en punto y coma (;). Así se pueden escribir varias seguidas.
  • A SQL le dan igual las mayúsculas en sus palabras (select o SELECT), pero se escriben en MAYÚSCULAS para distinguirlas de los nombres de tablas y columnas.
  • Escribe los nombres de tablas y columnas siempre igual que se crearon. En Windows MySQL no distingue articulos de Articulos, pero en un servidor Linux son dos tablas distintas. Evita los espacios y las tildes en los nombres: PrecioVenta, Fecha_alta.
  • Los textos y las fechas van entre comillas simples: 'Nokia', '2025-03-12'. Las fechas, con el formato año-mes-día. Los números, sin comillas y con punto decimal: 149.99.
  • Una sentencia puede ocupar varias líneas: los espacios y los saltos de línea dan igual, así que úsalos para que se lea bien.
  • Los comentarios son notas que SQL no ejecuta. Con -- (dos guiones y un espacio) el comentario llega hasta el final de la línea. Con /* … */ puede ocupar varias líneas.
-- Artículos baratos (esto es un comentario)
SELECT Nombre, Precio
FROM Articulos
WHERE Precio < 20;   /* esto también */

2. Crear y modificar tablas

Las órdenes de este apartado (DDL) no tocan los datos: crean, cambian o borran la estructura de la base de datos, es decir, las tablas y sus columnas.

Crear y elegir la base de datos

CREATE DATABASE TiendaInformatica;   -- crea una base de datos vacía
SHOW DATABASES;                      -- lista las bases de datos que hay
USE TiendaInformatica;               -- entra en ella: lo siguiente se hace dentro

En MySQL, después de USE, todas las tablas que crees se guardan en esa base de datos. En el editor de esta web ya estás dentro de una base de datos, así que estas órdenes no cambian nada (pero en tus archivos .sql ponlas siempre al principio). Para ver las tablas de la base de datos en la que estás: SHOW TABLES;.

Crear una tabla: CREATE TABLE

Para crear una tabla se escribe su nombre y, entre paréntesis y separadas por comas, sus columnas. De cada columna se pone el nombre, el tipo de dato y, si hace falta, algunas opciones. Lo que va entre corchetes es opcional (los corchetes no se escriben):

CREATE TABLE NombreTabla (
    columna1 TIPO [NOT NULL] [DEFAULT valor] [AUTO_INCREMENT] [PRIMARY KEY] [COMMENT 'nota'],
    columna2 TIPO [opciones],
    ...
);

Los tipos de datos que más vas a usar (los tienes explicados en la teoría de diseño):

Tipo Qué guarda Ejemplo
INT Números enteros Códigos, unidades, edad
DECIMAL(8,2) Números con decimales exactos: 8 cifras en total, 2 de ellas decimales (hasta 999999.99) Precios, notas
VARCHAR(n) Texto de hasta n caracteres Nombres, correos
CHAR(n) Texto de longitud fija DNI: CHAR(9)
TEXT Textos largos Descripciones, observaciones
DATE / DATETIME Fecha ('2025-03-12') / fecha y hora ('2025-03-12 09:30:00') Fecha de alta, de un pedido
BOOLEAN Sí o no (MySQL lo guarda como 1 o 0) ¿Está en oferta?

Y las opciones de cada columna:

  • NOT NULL: la columna es obligatoria, no puede quedar vacía. Si no lo pones, se permite NULL.
  • DEFAULT valor: el valor por defecto, el que se guarda si al añadir una fila no se indica otro.
  • PRIMARY KEY: la clave primaria. Sus valores no se pueden repetir ni quedar vacíos. Solo hay una por tabla.
  • AUTO_INCREMENT: solo para enteros, y casi siempre en la clave primaria. Si al añadir una fila no le das valor, MySQL pone el siguiente número (1, 2, 3…).
  • COMMENT 'nota': una explicación de la columna para quien la lea. No cambia nada.

Ejemplo: una tabla de clientes. Ejecútalo y mira el resultado del DESCRIBE.

Clave primaria compuesta

A veces ninguna columna sola sirve para identificar cada fila, pero dos juntas sí. Por ejemplo, en una tabla de notas un alumno tiene muchas notas (una por módulo) y un módulo tiene notas de muchos alumnos, pero la pareja alumno + módulo no se repite nunca. Entonces la clave primaria es compuesta y se escribe al final, después de las columnas:

PRIMARY KEY (columna1, columna2)

En el ejemplo, el tercer INSERT da error porque repite la pareja (1, 'AO'). Cambia el módulo por otro y vuelve a ejecutar.

Esta forma de escribir la clave al final también vale para una clave de una sola columna: PRIMARY KEY (Codigo).

Borrar una tabla: DROP TABLE

DROP TABLE Clientes;             -- borra la tabla con todos sus datos
DROP TABLE IF EXISTS Clientes;   -- igual, pero sin error si la tabla no existe

DROP TABLE no pide confirmación y no se puede deshacer. Con DROP DATABASE nombre; se borra la base de datos entera, con todas sus tablas.

Cambiar una tabla: ALTER TABLE

Si la tabla ya existe y tiene datos, no hace falta borrarla para cambiarla: se usa ALTER TABLE seguido de lo que quieres cambiar.

Sentencia Qué hace
ALTER TABLE Clientes RENAME TO Compradores; Cambia el nombre de la tabla.
ALTER TABLE Clientes ADD Telefono VARCHAR(15); Añade una columna al final.
ALTER TABLE Clientes ADD Dni CHAR(9) FIRST; Añade una columna al principio.
ALTER TABLE Clientes ADD Telefono VARCHAR(15) AFTER Nombre; Añade una columna detrás de otra.
ALTER TABLE Clientes DROP COLUMN Email; Borra una columna con todos sus datos.
ALTER TABLE Clientes ADD PRIMARY KEY (Codigo); Hace que una columna (o varias) sea la clave primaria.
ALTER TABLE Clientes DROP PRIMARY KEY; Quita la clave primaria (la columna se queda). Si es AUTO_INCREMENT, antes hay que quitárselo con MODIFY.
ALTER TABLE Clientes MODIFY Nombre VARCHAR(100) NOT NULL; Cambia el tipo o las opciones de una columna, sin cambiarle el nombre.
ALTER TABLE Clientes CHANGE Email Correo VARCHAR(80); Cambia el nombre de una columna (y, si quieres, su tipo).

Con MODIFY y CHANGE hay que escribir la definición completa de la columna: lo que no pongas (NOT NULL, DEFAULT…) se pierde. Puedes hacer varios cambios en un solo ALTER TABLE separándolos con comas: ALTER TABLE Clientes DROP COLUMN Email, ADD Movil VARCHAR(15);

Prueba a… cambiar la tabla Proveedores (ya está creada, como en el ejercicio anterior): añade una columna Email (texto de hasta 80) detrás de Nombre, borra la columna Pais y cambia el nombre de Telefono por Movil (mismo tipo).

Relacionar tablas: FOREIGN KEY

Una clave ajena (o foránea, foreign key) es una columna que guarda la clave primaria de otra tabla. En la tienda, Articulos.Fabricante guarda el código de un fabricante. Al declararla con FOREIGN KEY, MySQL vigila que siempre apunte a algo que existe: no deja guardar un artículo de un fabricante que no está en la tabla Fabricante.

CREATE TABLE TablaHija (
    ...,
    columna TIPO,
    FOREIGN KEY (columna) REFERENCES TablaPadre(clave_primaria)
        ON DELETE opción
        ON UPDATE opción
);

-- O, si la tabla ya existe:
ALTER TABLE TablaHija ADD FOREIGN KEY (columna) REFERENCES TablaPadre(clave_primaria);

La tabla a la que se apunta (la «padre») tiene que existir antes, y las dos columnas deben ser del mismo tipo. En MySQL las claves ajenas solo funcionan en tablas de tipo InnoDB, que es el que se usa por defecto; por eso en algunos manuales verás ENGINE=InnoDB al final del CREATE TABLE.

ON DELETE y ON UPDATE dicen qué pasa con las filas hijas cuando se borra la fila padre o se cambia su clave. Imagina que la tienda deja de trabajar con Nokia y borra ese fabricante, que tiene dos artículos:

Opción Qué pasa al borrar Nokia
RESTRICT (es la que se aplica si no escribes nada; NO ACTION hace lo mismo) No deja borrarlo: da error mientras tenga artículos.
CASCADE Borra Nokia y también sus dos artículos. Con ON UPDATE CASCADE, si cambias el código de Nokia, sus artículos se actualizan solos.
SET NULL Borra Nokia y sus artículos se quedan, pero sin fabricante (NULL). La columna no puede ser NOT NULL.

Ejecuta el ejemplo con CASCADE. Después cambia las dos palabras CASCADE por SET NULL y vuelve a ejecutar; luego, por RESTRICT.

3. Insertar, modificar y borrar datos

Con la tabla creada, toca llenarla. Las órdenes de este apartado (DML) trabajan con las filas: añadirlas (INSERT), cambiarlas (UPDATE) y borrarlas (DELETE).

Añadir filas: INSERT

-- Indicando las columnas (la forma recomendada)
INSERT INTO Tabla (columna1, columna2, ...) VALUES (valor1, valor2, ...);

-- Sin indicar las columnas: hay que dar un valor para cada una, en su orden
INSERT INTO Tabla VALUES (valor1, valor2, ...);

-- Varias filas a la vez
INSERT INTO Tabla (columna1, columna2) VALUES (...), (...), (...);

-- Con SET (solo en MySQL)
INSERT INTO Tabla SET columna1 = valor1, columna2 = valor2;

Si indicas las columnas, puedes ponerlas en el orden que quieras y saltarte algunas: las que no pongas se quedan con su valor por defecto, con NULL o, si son AUTO_INCREMENT, con el número siguiente. Si no las indicas, tienes que conocer el orden de las columnas (míralo con DESCRIBE).

El artículo 34 se queda sin precio ni fabricante (NULL). Los errores más habituales al insertar: repetir una clave primaria (prueba a cambiar el 34 por 1), olvidar las comillas de un texto, poner más o menos valores que columnas, o usar un fabricante que no existe (prueba con 99 en lugar de 12).

Prueba a… añadir el fabricante TP-Link con el código 11 y su artículo «Router TP-Link Archer AX55», con el código 32 y un precio de 79.90 €.

Cambiar datos: UPDATE

UPDATE Tabla
SET columna1 = valor1, columna2 = valor2
WHERE condición;

SET dice qué columnas cambian y WHERE, en qué filas. El nuevo valor puede calcularse a partir del antiguo: SET Precio = Precio * 0.90 rebaja un 10 %.

Sin WHERE, UPDATE cambia TODAS las filas de la tabla. UPDATE Articulos SET Precio = 0; deja gratis toda la tienda, y en MySQL no hay botón de deshacer. Un buen truco: antes de un UPDATE o un DELETE, ejecuta un SELECT con el mismo WHERE para ver qué filas vas a cambiar.

Borrar filas: DELETE y TRUNCATE

DELETE FROM Tabla WHERE condición;   -- borra las filas que cumplen la condición
DELETE FROM Tabla;                   -- borra TODAS las filas (la tabla se queda, vacía)
TRUNCATE Tabla;                      -- vacía la tabla de golpe

Igual que con UPDATE: sin WHERE, DELETE borra todas las filas. TRUNCATE también vacía la tabla, pero es más rápido (borra la tabla y la vuelve a crear vacía) y además reinicia el contador de AUTO_INCREMENT, que vuelve a empezar por 1. No confundas estas órdenes con DROP TABLE, que borra la tabla misma.

Borrar cuando hay claves ajenas

En la tienda, la clave ajena de Articulos no tiene ON DELETE, así que se aplica RESTRICT: se puede borrar un fabricante sin artículos (Alcatel, el 3), pero no uno que los tiene (Nokia, el 1). Ejecuta el ejemplo: la segunda sentencia da error.

Para borrar Nokia, primero hay que borrar sus artículos (DELETE FROM Articulos WHERE Fabricante = 1;) o cambiarlos de fabricante con un UPDATE. Añade una de las dos cosas antes del segundo DELETE y vuelve a ejecutar. Por la misma razón, MySQL no deja hacer TRUNCATE de una tabla a la que apunta una clave ajena, como Fabricante.

4. Consultas a una tabla

Consultar es lo que más se hace con una base de datos. Una consulta empieza siempre por SELECT y no cambia nada: solo enseña datos. Su forma básica es esta (solo son obligatorias las dos primeras líneas):

SELECT columnas
FROM tabla
WHERE condición
ORDER BY columna [ASC | DESC]
LIMIT cantidad;

Elegir las columnas

  • SELECT * FROM Articulos;: el asterisco significa «todas las columnas».
  • SELECT Nombre, Precio FROM Articulos;: solo las columnas que pongas, en ese orden.
  • Columnas calculadas: puedes operar con las columnas. Precio * 1.21 da el precio con IVA. La tabla no cambia: el cálculo solo se enseña.
  • AS cambia el título de una columna en el resultado: Precio * 1.21 AS PrecioIVA. Si el nuevo nombre lleva espacios, ponlo entre comillas: AS 'Precio con IVA'.
  • DISTINCT quita las filas repetidas del resultado.

Filtrar filas con WHERE

WHERE se queda solo con las filas que cumplen una condición. Para escribir condiciones se usan los operadores de comparación: = (igual), <> o != (distinto), <, >, <= y >=. Sirven para números, para textos (por orden alfabético) y para fechas.

Para juntar varias condiciones se usan los operadores lógicos:

  • AND (y): se tienen que cumplir las dos. WHERE Fabricante = 8 AND Precio < 100
  • OR (o): basta con que se cumpla una. WHERE Fabricante = 2 OR Fabricante = 5
  • NOT (no): da la vuelta a la condición. WHERE NOT Fabricante = 4

Si mezclas AND y OR, usa paréntesis: AND se calcula antes que OR, igual que en matemáticas se multiplica antes de sumar. Compara estas dos consultas:

BETWEEN, IN y LIKE

  • BETWEEN a AND b: entre dos valores, incluidos los dos. WHERE Precio BETWEEN 100 AND 200 es lo mismo que WHERE Precio >= 100 AND Precio <= 200.
  • IN (lista): igual a alguno de los valores de la lista. WHERE Fabricante IN (2, 5, 6) ahorra escribir tres OR.
  • LIKE: textos que siguen un patrón. El % vale por cualquier cantidad de caracteres (también ninguno) y el _, por exactamente uno. 'Monitor%': empieza por «Monitor»; '%Pro%': contiene «Pro»; 'iPhone __': «iPhone», un espacio y dos caracteres más. En MySQL, LIKE no distingue mayúsculas de minúsculas.
  • Delante de los tres se puede poner NOT: NOT BETWEEN, NOT IN, NOT LIKE.

Valores vacíos: IS NULL

NULL no es cero ni un texto vacío: significa «sin valor, no se sabe». Por eso no se puede comparar con = (WHERE Fabricante = NULL no devuelve nada nunca). Se usa IS NULL o IS NOT NULL. Ojo también con <>: WHERE Fabricante <> 8 no devuelve los artículos sin fabricante, porque de un valor desconocido no se puede decir que sea distinto de 8.

Ordenar y limitar: ORDER BY y LIMIT

  • ORDER BY columna ordena el resultado de menor a mayor (ASC, la opción por defecto) o de mayor a menor (DESC). Los textos se ordenan alfabéticamente.
  • Puedes ordenar por varias columnas: ORDER BY Fabricante, Precio DESC ordena por fabricante y, dentro de cada fabricante, del más caro al más barato.
  • LIMIT n enseña solo las n primeras filas. LIMIT inicio, cantidad se salta las primeras: LIMIT 5, 10 enseña 10 filas a partir de la sexta (se empieza a contar en 0). Así se hacen las páginas de resultados de una tienda online.
  • Sin ORDER BY, el orden de las filas no está garantizado. Y LIMIT va siempre al final.

Resumen de operadores

Tipo Operadores Ejemplo
Aritméticos + - * / % (resto de la división) DIV (división entera) Precio * 1.21
Comparación = <> != < > <= >= Precio >= 100
Lógicos AND OR NOT Fabricante = 8 AND Precio < 100
Rango BETWEEN … AND … Precio BETWEEN 100 AND 200
Lista IN (…) NOT IN (…) Fabricante IN (2, 5, 6)
Patrón LIKE con % y _ Nombre LIKE 'Monitor%'
Vacío IS NULL IS NOT NULL Fabricante IS NULL

5. Funciones y agrupación

Hasta ahora cada fila del resultado era una fila de la tabla. Con las funciones de resumen la base de datos hace cuentas con muchas filas a la vez: cuántos artículos hay, cuál es el precio medio… Y con GROUP BY, esas cuentas se hacen por grupos: por ejemplo, por fabricante.

Funciones de resumen

Función Qué devuelve
COUNT(*) Cuántas filas hay.
COUNT(columna) Cuántas filas tienen un valor en esa columna (no cuenta los NULL).
COUNT(DISTINCT columna) Cuántos valores distintos hay en esa columna.
SUM(columna) La suma.
AVG(columna) La media (average).
MAX(columna) / MIN(columna) El valor más alto / más bajo.

Todas se saltan los NULL. Sin GROUP BY, una consulta con estas funciones devuelve una sola fila. Para que la media no salga con muchos decimales, usa ROUND(número, decimales). Si hay WHERE, las cuentas se hacen solo con las filas que lo cumplen.

En el primer resultado sale 31, 29 y 8: hay 31 artículos, 29 tienen fabricante y entre todos son de 8 fabricantes distintos. Una trampa habitual: SELECT Nombre, MAX(Precio) FROM Articulos; no da el nombre del artículo más caro. Según la versión de MySQL, da error o un nombre cualquiera. Para eso, ordena y usa LIMIT 1, o una subconsulta (apartado 7).

Agrupar filas: GROUP BY

GROUP BY columna junta en un grupo todas las filas que tienen el mismo valor en esa columna y calcula las funciones de resumen para cada grupo. El resultado tiene una fila por grupo.

SELECT columna, FUNCIÓN(...)
FROM tabla
GROUP BY columna;

Los artículos sin fabricante forman su propio grupo, el de NULL. La regla de oro: en el SELECT de una consulta con GROUP BY solo puede haber columnas que estén en el GROUP BY y funciones de resumen.

Filtrar grupos: HAVING

HAVING es como un WHERE para los grupos: va después del GROUP BY y puede usar funciones de resumen. Por ejemplo, los fabricantes con más de 3 artículos:

WHERE HAVING
Filtra filas, antes de agrupar. Filtra grupos, después de agrupar.
No puede usar COUNT, SUM, AVG… Se usa justo con esas funciones: HAVING COUNT(*) > 3.
WHERE Precio > 100: solo cuentan los artículos de más de 100 €. HAVING AVG(Precio) > 100: solo salen los fabricantes cuya media pasa de 100 €.

El orden de las cláusulas

Las partes de un SELECT se escriben siempre en este orden. Ninguna es obligatoria salvo las dos primeras, pero las que pongas tienen que ir en su sitio:

SELECT    columnas y funciones
FROM      tabla
WHERE     condición sobre las filas
GROUP BY  columnas para agrupar
HAVING    condición sobre los grupos
ORDER BY  columnas para ordenar
LIMIT     cantidad;

Además de las de resumen, MySQL tiene muchas funciones que trabajan fila a fila. Algunas que te pueden venir bien:

Función Qué hace
CONCAT(a, b, …) Junta textos: CONCAT(Nombre, ' (', Precio, ' €)').
UPPER(texto) / LOWER(texto) Pasa a mayúsculas / minúsculas.
LENGTH(texto) Longitud de un texto. En MySQL cuenta bytes (una letra con tilde cuenta 2); para contar letras está CHAR_LENGTH.
ROUND(número, decimales) Redondea.
NOW() / CURDATE() Fecha y hora de ahora / fecha de hoy.
YEAR(fecha) / MONTH(fecha) El año / el mes de una fecha: WHERE YEAR(Alta) = 2025.

6. Consultas con varias tablas

En la tabla Articulos no está el nombre del fabricante, solo su código: el nombre está en Fabricante. Es lo normal en una base de datos bien diseñada, porque así cada dato se guarda una sola vez. Para sacar «nombre del artículo y nombre de su fabricante» hay que unir (en inglés, join) las dos tablas.

El producto cartesiano

Si pones dos tablas en el FROM separadas por una coma, sin más, SQL combina cada fila de la primera con cada fila de la segunda. Es el producto cartesiano: 31 artículos × 10 fabricantes = 310 filas, casi todas sin sentido (el iPhone con Nokia, con Xiaomi, con Alcatel…).

De todas esas combinaciones solo interesan las que emparejan cada artículo con su fabricante: aquellas en las que Articulos.Fabricante = Fabricante.Codigo. Esa condición es la que pone el JOIN.

Unir dos tablas: INNER JOIN

SELECT columnas
FROM Tabla1
INNER JOIN Tabla2 ON Tabla1.columna = Tabla2.columna;

Después de ON va la condición que empareja las filas: casi siempre, clave ajena = clave primaria. Como las dos tablas tienen columnas que se llaman igual (Codigo y Nombre), hay que poner delante el nombre de la tabla y un punto: Fabricante.Nombre. La palabra INNER se puede omitir: JOIN a secas es lo mismo.

Salen 29 filas, no 31: INNER JOIN solo devuelve las filas que tienen pareja en la otra tabla, y el cable y la alfombrilla no tienen fabricante. También verás escrita la unión a la antigua, con coma y WHERE: FROM Articulos, Fabricante WHERE Articulos.Fabricante = Fabricante.Codigo. Da el mismo resultado, pero con JOIN se lee mejor.

Alias de tablas

Para no escribir tantas veces el nombre de las tablas, se les da un nombre corto (un alias) en el FROM, con o sin AS: FROM Articulos A. A partir de ahí se escribe A.Nombre. Con la unión hecha, puedes añadir WHERE, ORDER BY y todo lo demás, y usar columnas de las dos tablas:

LEFT JOIN y RIGHT JOIN

A veces interesan también las filas que no tienen pareja: los fabricantes sin artículos o los artículos sin fabricante. Para eso están las uniones externas. LEFT (izquierda) es la tabla que está antes del JOIN y RIGHT (derecha), la de después.

Unión Qué devuelve
Fabricante F INNER JOIN Articulos A Solo las parejas fabricante-artículo. Ni Alcatel ni Sony ni el cable ni la alfombrilla.
Fabricante F LEFT JOIN Articulos A Las parejas y, además, todos los fabricantes: Alcatel y Sony salen una vez, con las columnas del artículo a NULL.
Fabricante F RIGHT JOIN Articulos A Las parejas y, además, todos los artículos: el cable y la alfombrilla salen con las columnas del fabricante a NULL.

Y aquí está el truco: como lo que no tiene pareja sale con NULL, si añades WHERE … IS NULL te quedas solo con lo que no tiene pareja.

Un RIGHT JOIN siempre se puede escribir como LEFT JOIN cambiando el orden de las tablas: FROM Articulos A LEFT JOIN Fabricante F … da lo mismo que el último ejemplo.

7. Subconsultas

Para ir más allá. Las subconsultas no son imprescindibles para empezar, pero resuelven de forma sencilla preguntas que de otra manera serían difíciles.

Una subconsulta es un SELECT metido dentro de otro, entre paréntesis. Primero se calcula la subconsulta y su resultado se usa en la consulta principal, casi siempre en el WHERE. Por ejemplo, para saber qué artículos cuestan más que la media hay dos pasos: calcular la media y comparar cada precio con ella. Con una subconsulta se hacen los dos a la vez:

SELECT Nombre, Precio
FROM Articulos
WHERE Precio > (SELECT AVG(Precio) FROM Articulos);

Hay dos casos:

  • Si la subconsulta devuelve un solo valor (una fila y una columna, como una media o un máximo), se compara con =, >, <…
  • Si devuelve una lista de valores (una columna con varias filas), se usa IN o NOT IN. (También existen ANY y ALL, que no vas a necesitar.)

En el último ejemplo, el WHERE Fabricante IS NOT NULL de la subconsulta hace falta: si en la lista de un NOT IN hay algún NULL, la consulta no devuelve nada (no se puede asegurar que un valor sea distinto de uno desconocido). Quítalo y verás. Muchas consultas se pueden hacer con subconsulta o con JOIN: usa la que entiendas mejor.

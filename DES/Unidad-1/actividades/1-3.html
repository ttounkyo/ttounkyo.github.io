Actividad 1.3. Usuario para el despliegue

Vas a crear en tu servidor un usuario llamado despliegue, con permisos de administrador y acceso por SSH con clave, y vas a impedir que root entre por SSH.

Lo que vas a practicar

  • adduser y usermod -aG sudo
  • Dar acceso SSH con clave a otro usuario
  • Propietario y permisos de .ssh (chown, chmod)
  • La directiva PermitRootLogin

Antes de empezar

  • Teoría: 4. Configuración del servidor SSH
  • Haber terminado la actividad 1.2: entras en el servidor con tu clave.

Paso a paso

  1. Crea el usuario despliegue

    Conéctate al servidor con tu usuario y crea el nuevo usuario. Te pedirá una contraseña segura y unos datos (nombre completo, teléfono…) que puedes dejar en blanco pulsando Intro:

    sudo adduser despliegue

  2. Dale permisos de administrador

    Añádelo al grupo sudo para que pueda ejecutar comandos como administrador, y comprueba que aparece en el grupo:

    sudo usermod -aG sudo despliegue
groups despliegue

  3. Dale acceso por SSH con clave

    Elige una de las dos opciones.

    Opción A: usar la misma clave que ya tienes. Copia tu archivo authorized_keys al nuevo usuario y deja como propietario a despliegue. Cambia usuario por tu nombre de usuario:

    # Crear la carpeta .ssh del nuevo usuario
sudo mkdir -p /home/despliegue/.ssh

# Copiar las claves públicas autorizadas
sudo cp /home/usuario/.ssh/authorized_keys /home/despliegue/.ssh/

# Poner como propietario al nuevo usuario
sudo chown -R despliegue:despliegue /home/despliegue/.ssh

# Permisos de seguridad
sudo chmod 700 /home/despliegue/.ssh
sudo chmod 600 /home/despliegue/.ssh/authorized_keys

    Opción B: una clave nueva solo para este usuario. Es más segura y más realista, porque cada usuario tiene su propia clave:

    1. En tu ordenador, genera otra clave con PuTTYgen y guárdala con otro nombre (por ejemplo, id_despliegue.ppk).
    2. Conéctate con PuTTY como despliegue con su contraseña.
    3. Crea ~/.ssh/authorized_keys, pega la nueva clave pública y pon los permisos 700 y 600, como en la actividad 1.2.

  4. Comprueba la conexión

    Crea en PuTTY una sesión nueva con despliegue@IP_DEL_SERVIDOR y la clave privada que corresponda (la de siempre en la opción A, la nueva en la B). Guárdala y conéctate. Desde Mac o Linux: 

    ssh despliegue@IP_DEL_SERVIDOR

    Ya dentro, comprueba que puede usar sudo:

    sudo whoami

    Si responde root, todo está bien.

  5. Impide que root entre por SSH

    Abre la configuración del servidor SSH:

    sudo nano /etc/ssh/sshd_config

    Busca la línea PermitRootLogin, quítale el # si lo tiene y déjala así:

    PermitRootLogin no

    El valor por defecto en Debian es prohibit-password: root no puede entrar con contraseña, pero sí con clave. Con no, root no puede entrar por SSH de ninguna forma.

    Guarda, comprueba que el archivo no tiene errores (si no dice nada, está bien) y reinicia el servicio:

    sudo sshd -t
sudo systemctl restart ssh
    Antes de cerrar tu sesión, abre otra conexión como despliegue y comprueba que entras. Si algo ha ido mal, todavía puedes arreglarlo desde la sesión que tienes abierta. En una máquina virtual también puedes entrar siempre desde la ventana de VirtualBox.

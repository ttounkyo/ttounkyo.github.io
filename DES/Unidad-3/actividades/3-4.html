Actividad 3.4. Despliegue de aplicaciones Jakarta EE con WildFly

En el mundo empresarial, Java sigue siendo un estándar. Vas a instalar el servidor de aplicaciones WildFly, crear con Maven una aplicación web con un servlet, empaquetarla en un archivo WAR y desplegarla.

Lo que vas a practicar

  • Instalar el JDK, Maven y WildFly
  • Usar la consola de administración de WildFly
  • Crear un proyecto web con Maven y escribir un servlet
  • Empaquetar un WAR y desplegarlo copiándolo en deployments

Antes de empezar

  • Teoría: 5. Despliegue de aplicaciones Java
  • Esta práctica necesita más memoria que las anteriores: tu máquina virtual debe tener al menos 2 GB de RAM.
  • El puerto 8080 libre (en el primer paso detienes lo que lo ocupa).

Paso a paso

WildFly saca una versión nueva cada pocos meses. Los pasos usan la 42.0.0.Final; si en wildfly.org/downloads hay una más nueva, cambia el número en el paso 3. Las versiones actuales de WildFly usan Jakarta EE (paquetes jakarta.*), no el antiguo Java EE (javax.*).

  1. Libera el puerto 8080

    WildFly usa el puerto 8080. Mira qué contenedores tienes en marcha de la Actividad 3.3 y detenlos, y para también la API de la Actividad 3.1 si sigue con PM2:

    docker ps
docker stop mi-contenedor
cd ~/mi-wordpress && docker compose stop
cd ~
pm2 stop all
    Comprueba: sudo ss -tulpn | grep :8080 no muestra nada: el puerto está libre.

  2. Instala el JDK y Maven

    Instala el kit de desarrollo de Java (JDK) 21 y Maven, y comprueba las versiones:

    sudo apt update
sudo apt install -y openjdk-21-jdk maven
java -version
mvn -version
    Comprueba: java -version dice openjdk version "21... y mvn -version dice Apache Maven 3.9... y Java version: 21....

  3. Descarga e instala WildFly

    Descarga WildFly en /tmp, descomprímelo en /opt y crea un enlace /opt/wildfly para no tener que escribir la versión cada vez:

    WILDFLY_VERSION=42.0.0.Final
cd /tmp
wget https://github.com/wildfly/wildfly/releases/download/$WILDFLY_VERSION/wildfly-$WILDFLY_VERSION.tar.gz
sudo tar xf wildfly-$WILDFLY_VERSION.tar.gz -C /opt/
sudo ln -s /opt/wildfly-$WILDFLY_VERSION /opt/wildfly
    Comprueba: ls /opt/wildfly muestra carpetas como bin, standalone y modules.

  4. Crea el usuario de administración

    sudo /opt/wildfly/bin/add-user.sh

    Responde a las preguntas:

    • Tipo de usuario: Management User (opción a).
    • Nombre de usuario: admin.
    • Contraseña: elige una segura y apúntala (no la pongas en las capturas).
    • Resto de preguntas: yes o Intro.
    Comprueba: al final sale Added user 'admin' to file ...mgmt-users.properties.

  5. Arranca WildFly

    Arranca el servidor en modo standalone permitiendo el acceso desde fuera a las aplicaciones (-b 0.0.0.0) y a la consola de administración (-bmanagement 0.0.0.0). Abrir la consola a todo el mundo está bien para practicar, pero ¡cuidado en producción!

    sudo /opt/wildfly/bin/standalone.sh -b 0.0.0.0 -bmanagement 0.0.0.0
    Comprueba: tras unos segundos sale una línea como WFLYSRV0025: WildFly 42.0.0.Final (WildFly Core ...) started in ...ms. Deja esta terminal abierta: aquí verás los logs.

    En el navegador, abre:

    • http://IP-DE-TU-SERVIDOR:8080: la página de bienvenida de WildFly.
    • http://IP-DE-TU-SERVIDOR:9990: la consola de administración (entra con el usuario admin).
    Si usas AWS: abre los puertos 8080 y 9990 en el grupo de seguridad.

    Captura: la consola de administración de WildFly funcionando.

  6. Genera el proyecto con Maven

    Abre otra conexión SSH (deja WildFly en marcha en la primera). Genera una aplicación web a partir de la plantilla (arquetipo) maven-archetype-webapp:

    cd ~
mvn archetype:generate \
    -DgroupId=com.ejemplo \
    -DartifactId=mi-webapp-java \
    -DarchetypeArtifactId=maven-archetype-webapp \
    -DarchetypeVersion=1.4 \
    -DinteractiveMode=false
cd mi-webapp-java
    Comprueba: la primera vez descarga muchas cosas y termina con BUILD SUCCESS. Dentro de mi-webapp-java hay un pom.xml y la carpeta src/main/webapp con index.jsp y WEB-INF/web.xml.

  7. Prepara el pom.xml

    El pom.xml que crea el arquetipo es antiguo (usa Java 7, que el JDK 21 ya no admite). Ábrelo y sustituye todo su contenido por este. Añade la dependencia de la API de Servlet de Jakarta EE, indica que se compila para Java 21 y que el WAR se llame mi-webapp-java.war:

    nano pom.xml
    <?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.ejemplo</groupId>
  <artifactId>mi-webapp-java</artifactId>
  <version>1.0-SNAPSHOT</version>
  <packaging>war</packaging>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <dependencies>
    <!-- API de Servlet de Jakarta EE: la pone el servidor (provided) -->
    <dependency>
      <groupId>jakarta.servlet</groupId>
      <artifactId>jakarta.servlet-api</artifactId>
      <version>6.0.0</version>
      <scope>provided</scope>
    </dependency>
  </dependencies>

  <build>
    <finalName>mi-webapp-java</finalName>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-compiler-plugin</artifactId>
        <version>3.13.0</version>
      </plugin>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-war-plugin</artifactId>
        <version>3.4.0</version>
      </plugin>
    </plugins>
  </build>
</project>

  8. Actualiza el web.xml

    El web.xml del arquetipo es de una versión muy antigua de los servlets y con él el servidor no lee las anotaciones como @WebServlet. Sustitúyelo por uno de Jakarta EE:

    nano src/main/webapp/WEB-INF/web.xml
    <?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">
    <display-name>mi-webapp-java</display-name>
</web-app>

  9. Crea el servlet «Hola Mundo»

    Crea la carpeta del código Java y el archivo del servlet:

    mkdir -p src/main/java/com/ejemplo
nano src/main/java/com/ejemplo/HelloServlet.java
    package com.ejemplo;

import java.io.IOException;
import java.io.PrintWriter;

import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet(name = "helloServlet", value = "/hello-servlet")
public class HelloServlet extends HttpServlet {
    @Override
    public void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        response.setContentType("text/html;charset=UTF-8");

        PrintWriter out = response.getWriter();
        out.println("<html><body>");
        out.println("<h1>¡Hola desde Jakarta EE y WildFly!</h1>");
        out.println("<p>Este es un Servlet compilado con Maven.</p>");
        out.println("</body></html>");
    }
}
    La anotación @WebServlet dice en qué dirección responde el servlet: /hello-servlet. Los import empiezan por jakarta.: si usaras los antiguos javax.servlet, WildFly no reconocería el servlet y daría un error 404.

    Captura: la estructura del proyecto (por ejemplo, con tree o find . -type f -not -path "./target/*").

  10. Construye el WAR

    mvn clean package
ls target/
    Comprueba: Maven termina con BUILD SUCCESS y en target/ está mi-webapp-java.war.

    Captura: el mvn package terminado con éxito.

  11. Despliega el WAR en WildFly

    La forma más sencilla es copiar el WAR en la carpeta de despliegues: WildFly lo detecta solo.

    sudo cp target/mi-webapp-java.war /opt/wildfly/standalone/deployments/
ls /opt/wildfly/standalone/deployments/
    Comprueba: en la terminal de WildFly sale WFLYSRV0010: Deployed "mi-webapp-java.war", y en la carpeta aparece un archivo mi-webapp-java.war.deployed. Si aparece mi-webapp-java.war.failed, lee el error en el log de WildFly.

  12. Prueba la aplicación

    Abre en el navegador:

    • http://IP-DE-TU-SERVIDOR:8080/mi-webapp-java/: la página index.jsp del arquetipo (Hello World!).
    • http://IP-DE-TU-SERVIDOR:8080/mi-webapp-java/hello-servlet: tu servlet (¡Hola desde Jakarta EE y WildFly!).

    Busca también la aplicación en la consola de administración, en Deployments.

    Captura: el navegador con la respuesta de tu servlet.

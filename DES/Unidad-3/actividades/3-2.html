Actividad 3.2. Despliegue de aplicaciones con Flask y Gunicorn

Vas a crear un «Hola Mundo» con Flask, uno de los frameworks web más populares de Python, y después un blog sencillo con base de datos. Lo pondrás en producción con Gunicorn como servicio del sistema y Nginx delante.

Lo que vas a practicar

  • Entornos virtuales de Python y pip
  • Una aplicación Flask con plantillas y base de datos SQLite
  • Gunicorn como servidor WSGI y servicio de systemd
  • Nginx como proxy inverso
  • Las dependencias en requirements.txt

Antes de empezar

  • Teoría: 7. Despliegue de aplicaciones Python
  • Tu servidor Debian 13 con conexión por SSH. Si hiciste la Actividad 3.1, en el primer paso liberas los puertos que ocupa.

Paso a paso

Las versiones de Python, Flask y Gunicorn cambian a menudo. Si en tu terminal salen números distintos a los de las capturas, no pasa nada.

  1. Libera los puertos de las prácticas anteriores

    Si tienes en marcha servicios de otras prácticas (Apache, la API de Node.js…), detenlos para que no ocupen los puertos que vas a usar. Si alguno no está instalado, verás un aviso; no pasa nada.

    sudo systemctl stop apache2
pm2 stop all

  2. Comprueba Python e instala pip y venv

    Debian 13 trae Python 3.13 instalado. Compruébalo e instala lo necesario para trabajar con Python:

    python3 --version
sudo apt update
sudo apt install -y python3-pip python3-venv python3-dev build-essential
    • python3-pip: el gestor de paquetes de Python.
    • python3-venv: para crear entornos virtuales.
    • python3-dev: archivos de desarrollo de Python.
    • build-essential: herramientas de compilación que necesitan algunos paquetes.
    pip3 --version
    Comprueba: salen las versiones, algo así como Python 3.13.5 y pip 25.1.1 from /usr/lib/python3/dist-packages/pip (python 3.13).

    Captura: las versiones de Python y pip.

  3. Crea tu primer proyecto con su entorno virtual

    Crea la carpeta del proyecto y, dentro, un entorno virtual. Se crea una carpeta venv con una instalación de Python limpia y aislada:

    mkdir ~/mi-primera-flask
cd ~/mi-primera-flask
python3 -m venv venv
source venv/bin/activate

    Al activarlo, el símbolo del sistema empieza por (venv):

    (venv) usuario@Debian13:~/mi-primera-flask$

    Mientras veas (venv), todo lo que instales con pip se queda en este proyecto. Instala Flask:

    pip install Flask
    Comprueba: la instalación termina con Successfully installed ... Flask-....

  4. Escribe y arranca el «Hola Mundo»

    nano app.py

    Copia este código y guarda (Ctrl+O, Intro, Ctrl+X): 

    from flask import Flask

app = Flask(__name__)

@app.route('/')
def hola_mundo():
    return '¡Hola Mundo desde Flask!'

@app.route('/sobre')
def sobre():
    return 'Esta es mi primera aplicación Flask en Debian'

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=True)
    • @app.route('/'): decorador que define la ruta principal.
    • host='0.0.0.0': acepta conexiones desde cualquier IP (necesario para entrar desde tu ordenador).
    • port=5000: el puerto donde escucha.
    • debug=True: modo depuración (se recarga solo al cambiar el código).
    python app.py

    Deberías ver algo así:

     * Serving Flask app 'app'
 * Debug mode: on
WARNING: This is a development server. Do not use it in a production deployment.
 * Running on all addresses (0.0.0.0)
 * Running on http://127.0.0.1:5000
 * Running on http://IP-DE-TU-SERVIDOR:5000

    Abre en el navegador http://IP-DE-TU-SERVIDOR:5000 y http://IP-DE-TU-SERVIDOR:5000/sobre.

    Si usas AWS: abre el puerto 5000 en el grupo de seguridad.

    Captura: la terminal con Flask en marcha y el navegador con las dos rutas.

    Para parar el servidor pulsa Ctrl+C; para salir del entorno virtual, escribe deactivate.

  5. Prepara el proyecto del blog

    Ahora vas a hacer una aplicación más completa, con formularios y una base de datos SQLite. Sal del entorno anterior, crea un proyecto nuevo con su propio entorno e instala Flask y Flask-SQLAlchemy (la extensión que facilita trabajar con bases de datos):

    deactivate
mkdir ~/flask-blog
cd ~/flask-blog
python3 -m venv venv
source venv/bin/activate
pip install Flask Flask-SQLAlchemy

  6. Escribe la aplicación del blog

    nano app.py
    from flask import Flask, render_template, request, redirect, url_for
from flask_sqlalchemy import SQLAlchemy
from datetime import datetime

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///blog.db'
app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False

db = SQLAlchemy(app)

# Modelo de datos para los posts
class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    titulo = db.Column(db.String(100), nullable=False)
    contenido = db.Column(db.Text, nullable=False)
    fecha = db.Column(db.DateTime, default=datetime.now)

    def __repr__(self):
        return f'<Post {self.titulo}>'

# Crea la base de datos y las tablas si no existen
# (aquí y no al final, para que también se haga al arrancar con Gunicorn)
with app.app_context():
    db.create_all()

# Ruta principal: lista los posts
@app.route('/')
def index():
    posts = Post.query.order_by(Post.fecha.desc()).all()
    return render_template('index.html', posts=posts)

# Ruta para crear un post
@app.route('/crear', methods=['GET', 'POST'])
def crear():
    if request.method == 'POST':
        titulo = request.form['titulo']
        contenido = request.form['contenido']
        nuevo_post = Post(titulo=titulo, contenido=contenido)

        db.session.add(nuevo_post)
        db.session.commit()

        return redirect(url_for('index'))

    return render_template('crear.html')

# Ruta para editar un post
@app.route('/editar/<int:id>', methods=['GET', 'POST'])
def editar(id):
    # Busca el post; si no existe, get_or_404 devuelve un error 404
    post = Post.query.get_or_404(id)

    # Si se envía el formulario (POST), se guardan los cambios
    if request.method == 'POST':
        post.titulo = request.form['titulo']
        post.contenido = request.form['contenido']
        db.session.commit()
        return redirect(url_for('index'))

    # Si solo se visita la página (GET), se muestra el formulario con los datos actuales
    return render_template('editar.html', post=post)

# Ruta para eliminar un post
@app.route('/eliminar/<int:id>')
def eliminar(id):
    post = Post.query.get_or_404(id)
    db.session.delete(post)
    db.session.commit()
    return redirect(url_for('index'))

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=True)

  8. Prueba el blog

    python app.py

    Entra en http://IP-DE-TU-SERVIDOR:5000 y prueba a crear varios posts, verlos en la lista, editar uno y eliminar otro.

    Comprueba: cada acción aparece en la terminal como una petición ("GET / HTTP/1.1" 200, "POST /crear HTTP/1.1" 302…) y en la carpeta del proyecto aparece la base de datos (instance/blog.db).

    Captura: la página principal con varios posts, el formulario de nuevo post y la terminal con las peticiones que recibe Flask.

  9. Prueba Gunicorn

    El servidor de desarrollo de Flask (python app.py) no sirve para producción. Vas a usar Gunicorn, un servidor WSGI robusto. Para Flask con Ctrl+C y, en la carpeta del proyecto y con el entorno activo, instala y prueba Gunicorn:

    cd ~/flask-blog
source venv/bin/activate
pip install gunicorn
gunicorn --bind 0.0.0.0:5000 app:app
    • --bind 0.0.0.0:5000: escucha en todas las interfaces, en el puerto 5000.
    • app:app: el primer app es el archivo (app.py) y el segundo, la variable de Flask dentro del archivo.
    Comprueba: sale Starting gunicorn, Listening at: http://0.0.0.0:5000 y Booting worker with pid, y el blog funciona en el navegador. Después detén Gunicorn con Ctrl+C.

  10. Convierte Gunicorn en un servicio

    Para que Gunicorn arranque solo y siga funcionando al cerrar la sesión, crea un servicio de systemd:

    sudo nano /etc/systemd/system/flask-blog.service

    Escribe esto cambiando tuUsuario por tu nombre de usuario en la línea User y en todas las rutas (lo ves con whoami):

    [Unit]
Description=Gunicorn para el blog de Flask
After=network.target

[Service]
User=tuUsuario
Group=www-data
WorkingDirectory=/home/tuUsuario/flask-blog
Environment="PATH=/home/tuUsuario/flask-blog/venv/bin"
ExecStart=/home/tuUsuario/flask-blog/venv/bin/gunicorn --workers 3 --bind 0.0.0.0:5000 app:app

[Install]
WantedBy=multi-user.target

    Recarga systemd, arranca el servicio, actívalo para que arranque con el sistema y mira su estado:

    sudo systemctl daemon-reload
sudo systemctl start flask-blog
sudo systemctl enable flask-blog
sudo systemctl status flask-blog
    Comprueba: el estado dice active (running) en verde y el blog sigue funcionando en el puerto 5000. Sal del estado con q.

    Comandos útiles para gestionar el servicio:

    # Ver los logs en tiempo real
sudo journalctl -u flask-blog -f

# Reiniciar, detener y ver el estado
sudo systemctl restart flask-blog
sudo systemctl stop flask-blog
sudo systemctl status flask-blog

    Captura: la salida de sudo systemctl status flask-blog con el servicio activo.

  11. Pon Nginx delante como proxy inverso

    Igual que con Node.js, Nginx recibirá las peticiones en el puerto 80 y las pasará a Gunicorn. Instala Nginx si no lo tienes y crea la configuración del sitio:

    sudo apt install -y nginx
sudo nano /etc/nginx/sites-available/flask-blog
    server {
    listen 80;
    server_name IP-DE-TU-SERVIDOR;  # o tu dominio

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Archivos estáticos (si los tuvieras)
    location /static {
        alias /home/tuUsuario/flask-blog/static;
    }
}

    Activa el sitio y desactiva los demás (el sitio por defecto y el de la Actividad 3.1, si existen), para que no respondan en su lugar. Comprueba la configuración y reinicia Nginx:

    sudo ln -s /etc/nginx/sites-available/flask-blog /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default /etc/nginx/sites-enabled/todo-app
sudo nginx -t
sudo systemctl restart nginx
    Comprueba: http://IP-DE-TU-SERVIDOR (sin puerto) muestra el blog. El recorrido queda así: Usuario → Nginx (puerto 80) → Gunicorn (puerto 5000) → aplicación Flask.

  13. Revisa los logs y resuelve problemas

    Deja los logs en marcha y entra en el blog desde el navegador para ver las peticiones en tiempo real:

    # Logs de la aplicación (Gunicorn)
sudo journalctl -u flask-blog -f

# Logs de Nginx
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log

# Últimas 50 líneas del servicio y búsqueda de errores
sudo journalctl -u flask-blog -n 50
sudo journalctl -u flask-blog | grep -i error
    Problema Qué mirar
    El servicio no arranca sudo systemctl status flask-blog y sudo journalctl -u flask-blog -n 50. Causas habituales: una ruta mal escrita en el .service, el usuario equivocado o que no encuentra el entorno virtual.
    Error 502 Bad Gateway en Nginx Que Gunicorn esté en marcha (sudo systemctl status flask-blog), que escuche en el puerto correcto (sudo ss -tulpn | grep :5000) y el log de errores de Nginx.
    Los cambios en el código no se ven Gunicorn no recarga solo: reinicia el servicio con sudo systemctl restart flask-blog.

Ampliación: despliegue en AWS

Esta parte se hará cuando tengas montado el servidor en AWS. Despliega la aplicación Flask en un servidor remoto:

  1. Prepara un servidor remoto (por ejemplo, un VPS en AWS).
  2. Instala Python, pip y Git en el servidor.
  3. Clona tu repositorio de GitHub en el servidor.
  4. Crea el entorno virtual e instala las dependencias con requirements.txt.
  5. Configura Gunicorn para que arranque la aplicación.
  6. Crea el servicio de systemd para que arranque al iniciar el sistema.
  7. Configura Nginx para que sirva la aplicación.
  8. Revisa los logs de la aplicación y de Nginx para asegurarte de que todo funciona.

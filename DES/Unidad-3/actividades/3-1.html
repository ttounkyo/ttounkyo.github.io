Actividad 3.1. Despliegue de aplicaciones con Node.js y Express

Vas a instalar Node.js en tu servidor Debian, crear un «Hola Mundo» con Express y desplegar una API de tutoriales con base de datos MariaDB. Al final la dejarás funcionando siempre con PM2 y detrás de Nginx.

Lo que vas a practicar

  • Instalar Node.js y npm, y gestionar dependencias con package.json
  • Crear y arrancar una aplicación Express
  • Conectar una API a MariaDB y probarla con curl
  • Mantener la aplicación en marcha con PM2
  • Poner Nginx como proxy inverso

Antes de empezar

  • Teoría: 6. Despliegue de aplicaciones Node.js con Express
  • Tu servidor Debian 13 de la Unidad 1 (máquina virtual o VPS), con un usuario con sudo y conexión por SSH.
  • La IP de tu servidor: la ves con ip a. En los pasos aparece como IP-DE-TU-SERVIDOR.

Paso a paso

Las versiones cambian a menudo: Debian 13 instala Node.js 20 desde sus repositorios, aunque la versión LTS actual de Node.js es más nueva. Para esta práctica sirve la de Debian. Si en tu terminal salen números de versión distintos a los de las capturas, no pasa nada.

  1. Instala Node.js y npm

    Conéctate por SSH a tu servidor. Actualiza la lista de paquetes e instala Node.js y npm (se instalan juntos; -y responde «sí» a la pregunta de confirmación):

    sudo apt update
sudo apt install -y nodejs npm

    Comprueba las versiones instaladas:

    node --version
npm --version
    Comprueba: salen dos números de versión, algo así:
    v20.19.2
9.2.0

    Captura: las versiones de node y npm.

  2. Instala el generador de Express

    Express se instala en cada proyecto, pero su generador de proyectos se instala para todo el sistema (-g, global):

    sudo npm install -g express-generator

    Si ves npm WARN deprecated mkdirp@0.5.1, es solo una advertencia: el paquete se ha instalado (sale added … packages), pero una dependencia interna usa una versión antigua. No afecta al funcionamiento.

    express --version
    Comprueba: sale la versión del generador, por ejemplo 4.16.1.

  3. Crea tu primer proyecto

    Crea una carpeta para la aplicación y entra en ella:

    mkdir ~/mi-primera-app
cd ~/mi-primera-app

    Inicializa el proyecto. Se crea el archivo package.json, que es como el «DNI» de la aplicación (-y acepta todas las opciones por defecto). Después instala Express solo para este proyecto:

    npm init -y
npm install express
    Comprueba: con ls ves node_modules, package.json y package-lock.json. Dentro de node_modules están Express y todas sus dependencias.

  4. Escribe y arranca el «Hola Mundo»

    Crea el archivo app.js:

    nano app.js

    Copia este código y guarda (Ctrl+O, Intro, Ctrl+X): 

    const express = require('express');
const app = express();
const puerto = 3000;

app.get('/', (req, res) => {
  res.send('¡Hola Mundo desde Express!');
});

app.listen(puerto, () => {
  console.log(`Servidor corriendo en http://localhost:${puerto}`);
});
    • require('express') importa la librería Express.
    • app.get('/', ...) dice qué hacer cuando alguien visita la raíz del sitio.
    • app.listen(puerto, ...) arranca el servidor en el puerto 3000.

    Arranca la aplicación:

    node app.js

    Abre en el navegador de tu ordenador http://IP-DE-TU-SERVIDOR:3000.

    Comprueba: en la terminal sale Servidor corriendo en http://localhost:3000 y en el navegador, ¡Hola Mundo desde Express!
    Si usas AWS: abre el puerto 3000 en el grupo de seguridad (tipo TCP personalizado, puerto 3000, origen tu IP o 0.0.0.0/0). Más adelante necesitarás también el 8080 y el 80.

    Captura: la terminal con node app.js en marcha y el navegador con el mensaje.

    Para parar el servidor, pulsa Ctrl+C en la terminal.

  5. Descarga la aplicación de tutoriales

    Ahora vas a desplegar una aplicación más completa: una API para gestionar tutoriales, guardados en una base de datos. Vuelve a tu carpeta personal, instala Git si no lo tienes y clona (descarga una copia completa) el proyecto de GitHub:

    cd ~
sudo apt install -y git
git clone https://github.com/bezkoder/nodejs-express-mysql.git
cd nodejs-express-mysql

    Mira qué hay dentro e instala las dependencias del proyecto. npm install lee package.json y descarga todas las librerías que necesita la aplicación (puede tardar un poco):

    ls -la
npm install
cat package.json
    Comprueba: ves server.js, package.json y la carpeta app/, y npm install termina con found 0 vulnerabilities o con un resumen sin errores.

  6. Instala MariaDB y crea la base de datos

    La aplicación guarda los tutoriales en una base de datos MySQL. En Debian se usa MariaDB, que es compatible:

    sudo apt install -y mariadb-server
sudo systemctl start mariadb
sudo systemctl enable mariadb

    Entra en MariaDB como administrador:

    sudo mysql -u root

    El símbolo del sistema cambia a MariaDB [(none)]>. Crea la base de datos, un usuario para la aplicación y la tabla tutorials (la aplicación no la crea sola). Cambia TU_CONTRASEÑA por una contraseña inventada y apúntala, porque la necesitas en el paso siguiente:

    CREATE DATABASE testdb;
CREATE USER 'testuser'@'localhost' IDENTIFIED BY 'TU_CONTRASEÑA';
GRANT ALL PRIVILEGES ON testdb.* TO 'testuser'@'localhost';
FLUSH PRIVILEGES;

USE testdb;
CREATE TABLE IF NOT EXISTS tutorials (
  id INT AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(255),
  description VARCHAR(255),
  published BOOLEAN DEFAULT false,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

EXIT;
    Comprueba: cada orden responde Query OK y al salir aparece Bye.

  7. Configura la conexión a la base de datos

    Edita el archivo de configuración de la aplicación:

    nano app/config/db.config.js

    Déjalo así, con el usuario, la contraseña y la base de datos del paso anterior:

    module.exports = {
  HOST: "localhost",
  USER: "testuser",
  PASSWORD: "TU_CONTRASEÑA",
  DB: "testdb"
};

  8. Arranca la API

    node server.js
    Comprueba: en la terminal sale Server is running on port 8080. y en el navegador, http://IP-DE-TU-SERVIDOR:8080 muestra un mensaje de bienvenida en JSON ({"message":"Welcome to bezkoder application."}).
    Si usas AWS: abre también el puerto 8080 en el grupo de seguridad.

  10. Mantén la aplicación en marcha con PM2

    Si cierras la terminal, la API se para. PM2 es un gestor de procesos que mantiene la aplicación en segundo plano y la reinicia sola si falla. Para la API con Ctrl+C, instala PM2 y arráncala con él (--name le da un nombre fácil de recordar):

    sudo npm install -g pm2
cd ~/nodejs-express-mysql
pm2 start server.js --name "todo-app"
pm2 list

    Comprueba que sigue funcionando sin la terminal: abre http://IP-DE-TU-SERVIDOR:8080/api/tutorials, cierra la sesión SSH, vuelve a conectarte y recarga la página.

    Comandos útiles de PM2:

    # Ver los registros (logs) en tiempo real
pm2 logs todo-app

# Reiniciar, detener o quitar la aplicación de PM2
pm2 restart todo-app
pm2 stop todo-app
pm2 delete todo-app

# Ver información detallada
pm2 show todo-app

    Por último, haz que PM2 arranque solo al encender el servidor. pm2 startup te muestra un comando que empieza por sudo env PATH=...: cópialo y ejecútalo. Después, pm2 save guarda la lista de aplicaciones actual:

    pm2 startup
pm2 save
    Comprueba: pm2 list muestra todo-app en online, y tras sudo reboot sigue en online sin que hagas nada.

    Captura: la salida de pm2 list y de pm2 logs todo-app (sales de los logs con Ctrl+C).

  11. Pon Nginx delante como proxy inverso

    En producción se pone Nginx delante de Node.js: Nginx recibe las peticiones en el puerto 80 y las pasa a la aplicación. Instálalo y crea un archivo de configuración para el sitio:

    sudo apt install -y nginx
sudo nano /etc/nginx/sites-available/todo-app

    Escribe esto. En server_name pon tu dominio o la IP de tu servidor:

    server {
    listen 80;
    server_name IP-DE-TU-SERVIDOR;

    location / {
        proxy_pass http://localhost:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

    Activa el sitio con un enlace simbólico, desactiva el sitio por defecto de Nginx, comprueba la configuración y reinicia:

    sudo ln -s /etc/nginx/sites-available/todo-app /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx
    Comprueba: sudo nginx -t responde syntax is ok y test is successful, y http://IP-DE-TU-SERVIDOR/api/tutorials (sin :8080) muestra la lista.

    Ventajas del proxy inverso:

    • Nginx gestiona HTTPS (SSL/TLS) de forma más eficiente.
    • Puede servir los archivos estáticos directamente.
    • Rinde mejor con mucha carga.
    • Con un solo Nginx puedes tener varias aplicaciones Node.js.

  12. Revisa los logs y resuelve problemas

    Deja los logs de PM2 en marcha y entra en la aplicación desde el navegador: verás las peticiones en tiempo real. Haz lo mismo con los logs de Nginx:

    pm2 logs todo-app

# Logs de acceso y de errores de Nginx
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log

    Provoca un error pidiendo una ruta que no existe y busca la petición en los logs:

    curl http://localhost:8080/api/noexiste

    Si algo falla, estos comandos te ayudan:

    Problema Qué mirar
    El servidor no arranca sudo ss -tulpn | grep :8080 (¿otro programa usa el puerto?) y pm2 logs todo-app --err
    No puedes conectarte desde fuera sudo ss -tulpn | grep :8080 debe mostrar que escucha en todas las interfaces (*:8080 o 0.0.0.0:8080). Si tienes cortafuegos, sudo ufw status; en AWS, revisa el grupo de seguridad.
    La aplicación se reinicia sin parar pm2 logs todo-app para ver el error y pm2 list para ver el estado
    Lee los mensajes de error enteros: suelen decir exactamente qué falla. La documentación oficial de Express es muy buena: expressjs.com.

Actividad 3.3. Despliegue de aplicaciones Node.js con Docker

Vas a instalar Docker, meter una aplicación Express en un contenedor con tu propio Dockerfile y, después, levantar un WordPress completo (web y base de datos) con Docker Compose usando imágenes oficiales.

Lo que vas a practicar

  • Instalar Docker Engine y Docker Compose en Debian
  • Escribir un Dockerfile y un .dockerignore
  • Construir una imagen y ejecutar un contenedor con puertos publicados
  • Levantar varios contenedores con docker compose y volúmenes

Antes de empezar

  • Teoría: 8. Contenedores: Docker
  • Tu servidor Debian 13 con un usuario con permisos de sudo.
  • Node.js y npm de la Actividad 3.1 (si no los tienes, mira el paso 5).

Paso a paso

Docker cambia a menudo su forma de instalarse. Si algún comando de los pasos 1 y 2 falla, sigue la guía oficial: Install Docker Engine on Debian. Ojo: el comando actual es docker compose (con espacio); el antiguo docker-compose (con guion) ya no se usa.

  1. Libera los puertos de las prácticas anteriores

    Vas a usar el puerto 8080, que en la Actividad 3.1 ocupaba la API con PM2. Detén lo que tengas en marcha (si algo no está instalado, verás un aviso; no pasa nada):

    pm2 stop all
sudo systemctl stop flask-blog

  2. Añade el repositorio oficial de Docker

    Docker no se instala desde los repositorios de Debian, sino desde el suyo. Primero instala lo necesario y descarga la clave con la que Docker firma sus paquetes:

    sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

    Después añade el repositorio. Copia el bloque entero: crea el archivo /etc/apt/sources.list.d/docker.sources con la versión de tu Debian:

    sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
    Comprueba: en la salida de sudo apt update aparece una línea con https://download.docker.com/linux/debian trixie sin errores.

  3. Instala Docker Engine

    sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker --version
sudo docker compose version

    Comprueba que funciona descargando y ejecutando el contenedor de prueba hello-world:

    sudo docker run hello-world
    Comprueba: salen las versiones de Docker y de Docker Compose, y el contenedor de prueba muestra el mensaje Hello from Docker!

    Captura: la versión de Docker instalada.

  4. Usa Docker sin sudo

    Para no tener que escribir sudo delante de cada comando, añade tu usuario al grupo docker y aplica el cambio (o cierra la sesión y vuelve a entrar):

    sudo usermod -aG docker $USER
newgrp docker
    Comprueba: docker ps (sin sudo) muestra una tabla vacía en lugar de un error de permisos.

  5. Prepara la aplicación Node.js

    Usarás una aplicación Express sencilla, como la de la Actividad 3.1:

    mkdir ~/docker-node-app
cd ~/docker-node-app
npm init -y
npm install express
    Si no tienes npm en este servidor, no instales nada: crea el package.json a mano con la dependencia de Express (en el siguiente bloque) y Docker instalará las dependencias dentro del contenedor.
    Ver un package.json mínimo 
    {
  "name": "docker-node-app",
  "version": "1.0.0",
  "main": "app.js",
  "dependencies": {
    "express": "^5.0.0"
  }
}

    Crea el archivo app.js:

    nano app.js
    const express = require('express');
const app = express();
const port = 3000;

app.get('/', (req, res) => {
  res.send('¡Hola desde un contenedor Docker! 🐳');
});

app.listen(port, () => {
  console.log(`App escuchando en http://localhost:${port}`);
});

  6. Escribe el Dockerfile y el .dockerignore

    El Dockerfile es la «receta» para construir la imagen de la aplicación. Créalo (sin extensión):

    nano Dockerfile
    # Imagen base oficial de Node.js: versión LTS, ligera (Alpine Linux)
FROM node:lts-alpine

# Directorio de trabajo dentro del contenedor
WORKDIR /app

# Copia los archivos de dependencias
COPY package*.json ./

# Instala las dependencias
RUN npm install

# Copia el resto del código
COPY . .

# Puerto que usa la aplicación
EXPOSE 3000

# Comando para arrancar la aplicación
CMD ["node", "app.js"]

    El .dockerignore evita copiar al contenedor archivos que no hacen falta, como tu node_modules local:

    nano .dockerignore
    node_modules
npm-debug.log

    Captura: el contenido del Dockerfile (por ejemplo, con cat Dockerfile).

  7. Construye la imagen

    docker build -t mi-node-app .

    -t mi-node-app pone nombre (etiqueta) a la imagen y el punto final indica que el Dockerfile está en la carpeta actual.

    docker images
    Comprueba: la construcción termina sin errores (con naming to docker.io/library/mi-node-app) y docker images muestra mi-node-app con la etiqueta latest.

    Captura: el proceso de construcción (docker build).

  8. Ejecuta el contenedor

    docker run -d -p 8080:3000 --name mi-contenedor mi-node-app
    • -d: modo detached, se ejecuta en segundo plano.
    • -p 8080:3000: une el puerto 8080 del servidor (host) con el puerto 3000 del contenedor.
    • --name mi-contenedor: le da un nombre fácil de recordar.
    docker ps
curl http://localhost:8080
    Comprueba: docker ps muestra mi-contenedor con el estado Up y los puertos 0.0.0.0:8080->3000/tcp; curl (o el navegador en http://IP-DE-TU-SERVIDOR:8080) devuelve ¡Hola desde un contenedor Docker! 🐳.

    Captura: la salida de docker ps y la prueba en el navegador o con curl.

  9. Gestiona el contenedor

    # Ver los logs del contenedor
docker logs mi-contenedor

# Detener el contenedor
docker stop mi-contenedor

# Eliminar el contenedor (tiene que estar detenido)
docker rm mi-contenedor
    Comprueba: el log muestra App escuchando en http://localhost:3000 y, al final, docker ps -a ya no muestra mi-contenedor. Así el puerto 8080 queda libre para WordPress.

  10. Prepara WordPress con Docker Compose

    Para WordPress no se escribe un Dockerfile: se usan imágenes oficiales ya creadas y se conectan entre sí. Hacen falta dos contenedores:

    • WordPress: el código PHP y el servidor web.
    • MariaDB: la base de datos donde se guarda todo.

    En lugar de lanzar comandos largos, se describe todo en un archivo docker-compose.yml:

    mkdir ~/mi-wordpress
cd ~/mi-wordpress
nano docker-compose.yml

    Pega este contenido. Cambia las contraseñas de ejemplo por otras inventadas (la de MYSQL_PASSWORD y la de WORDPRESS_DB_PASSWORD tienen que ser iguales):

    services:
  db:
    image: mariadb:11.8
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: contraseña_maestra
      MYSQL_DATABASE: wordpress
      MYSQL_USER: usuario_wp
      MYSQL_PASSWORD: contraseña_wp
    volumes:
      - db_data:/var/lib/mysql

  wordpress:
    image: wordpress:latest
    restart: always
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: usuario_wp
      WORDPRESS_DB_PASSWORD: contraseña_wp
      WORDPRESS_DB_NAME: wordpress
    volumes:
      - wp_data:/var/www/html

volumes:
  db_data:
  wp_data:

  11. Levanta WordPress y compruébalo

    docker compose up -d
docker compose ps

    -d hace que se ejecute en segundo plano. La primera vez tarda un poco porque descarga las imágenes.

    Comprueba: docker compose ps muestra los dos servicios (db y wordpress) en marcha, y http://IP-DE-TU-SERVIDOR:8080 abre el asistente de instalación de WordPress (empieza pidiendo el idioma). Si sale un error de conexión a la base de datos, espera unos segundos y recarga: MariaDB tarda un poco en arrancar.
    ¿Qué acaba de pasar?
    • Docker Compose: antes usaste docker build y docker run para un solo contenedor. Ahora docker compose gestiona varios a la vez y los conecta entre sí (WordPress encuentra la base de datos por el nombre db).
    • Persistencia (volúmenes): la sección volumes es vital. Si borras el contenedor de WordPress, tus fotos y artículos no se pierden porque están guardados en volúmenes con nombre en el disco del servidor, no «dentro» del contenedor, que es efímero.
    • Imágenes oficiales: no has creado ningún Dockerfile. Con image: wordpress:latest, Docker descarga de Docker Hub la imagen con todo ya preparado (Apache, PHP, etc.).

    Para pararlo todo sin borrar los datos: docker compose stop (o docker compose down para quitar también los contenedores; los volúmenes se conservan).

Actividad 3.5. Despliegue de aplicaciones Django (Python)

Vas a crear un proyecto con Django, el framework «con todo incluido» de Python, con su panel de administración y una pequeña aplicación. Lo desplegarás con Gunicorn escuchando en un socket Unix y Nginx sirviendo los archivos estáticos.

Lo que vas a practicar

  • Crear un proyecto y una aplicación Django
  • Migraciones y superusuario del panel de administración
  • Recolectar los archivos estáticos con collectstatic
  • Gunicorn con un socket Unix como servicio de systemd
  • Nginx como proxy inverso y servidor de estáticos

Antes de empezar

  • Teoría: 7. Despliegue de aplicaciones Python
  • Python, pip y venv instalados como en la Actividad 3.2 (paso 2).
  • Nginx instalado (Actividades 3.1 o 3.2).

Paso a paso

Django saca una versión nueva cada ocho meses. Los pasos sirven para las versiones actuales; si alguna pantalla o mensaje cambia un poco, busca el equivalente. En todos los archivos cambia tuUsuario por tu nombre de usuario (lo ves con whoami).

  1. Libera los puertos de las prácticas anteriores

    Detén los servicios de otras prácticas para que no ocupen los puertos (si alguno no existe, verás un aviso; no pasa nada). Si tienes WildFly en marcha, páralo con Ctrl+C en su terminal.

    sudo systemctl stop apache2
sudo systemctl stop flask-blog
pm2 stop all

  2. Prepara el entorno virtual e instala Django

    mkdir ~/mi-proyecto-django
cd ~/mi-proyecto-django
python3 -m venv venv
source venv/bin/activate
pip install django gunicorn
python -m django --version
    Comprueba: el símbolo del sistema empieza por (venv) y el último comando muestra la versión de Django (por ejemplo, 6.1.2).

  3. Crea el proyecto

    Genera la estructura del proyecto. El punto final es importante: crea el proyecto en la carpeta actual en lugar de en una subcarpeta más:

    django-admin startproject misitio .

    Aplica las migraciones iniciales (crean las tablas de la base de datos SQLite) y crea un superusuario para el panel de administración (te pedirá usuario, correo y contraseña):

    python manage.py migrate
python manage.py createsuperuser
    Comprueba: migrate muestra varias líneas Applying ... OK y al final sale Superuser created successfully.

  4. Prueba el servidor de desarrollo

    Para poder entrar desde otro equipo, permite cualquier nombre de host (solo para practicar). Abre la configuración:

    nano misitio/settings.py

    Busca ALLOWED_HOSTS y déjalo así:

    ALLOWED_HOSTS = ['*']

    Arranca el servidor de desarrollo:

    python manage.py runserver 0.0.0.0:8000

    Abre en el navegador:

    • http://IP-DE-TU-SERVIDOR:8000: verás el cohete de Django («The install worked successfully!»).
    • http://IP-DE-TU-SERVIDOR:8000/admin: el panel de administración. Entra con tu superusuario.
    Si usas AWS: abre el puerto 8000 en el grupo de seguridad.

    Captura: el panel de administración de Django funcionando.

  5. Crea una aplicación «Hola Mundo»

    En Django, un proyecto puede tener varias aplicaciones. Para el servidor (Ctrl+C) y crea una:

    python manage.py startapp hola

    Define una vista en hola/views.py (sustituye su contenido):

    nano hola/views.py
    from django.http import HttpResponse

def index(request):
    return HttpResponse("¡Hola Mundo desde Django en Debian!")

    Crea el archivo hola/urls.py con las rutas de la aplicación:

    nano hola/urls.py
    from django.urls import path
from . import views

urlpatterns = [
    path('', views.index, name='index'),
]

    Incluye esas rutas en las del proyecto, en misitio/urls.py (sustituye su contenido):

    nano misitio/urls.py
    from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('hola.urls')),
]

    Por último, añade 'hola' a la lista INSTALLED_APPS de misitio/settings.py:

    INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'hola',
]
    python manage.py runserver 0.0.0.0:8000
    Comprueba: http://IP-DE-TU-SERVIDOR:8000 muestra ahora ¡Hola Mundo desde Django en Debian! y /admin sigue funcionando. Después para el servidor con Ctrl+C.

  6. Recolecta los archivos estáticos

    En producción Django no sirve bien los archivos estáticos (CSS, JavaScript, imágenes): los reúne en una carpeta para que los sirva Nginx. Añade al final de misitio/settings.py:

    STATIC_ROOT = BASE_DIR / 'static'

    Y recolecta los estáticos (confirma con yes si te lo pregunta):

    python manage.py collectstatic
    Comprueba: sale ... static files copied to '/home/tuUsuario/mi-proyecto-django/static' (son los estilos del panel de administración).

  7. Prueba Gunicorn con un socket Unix

    Esta vez Gunicorn no escuchará en un puerto TCP, sino en un socket Unix: un archivo especial por el que Nginx y Gunicorn se comunican dentro del mismo servidor.

    gunicorn --bind unix:/home/tuUsuario/mi-proyecto-django/misitio.sock misitio.wsgi:application
    Comprueba: sale Listening at: unix:/home/tuUsuario/mi-proyecto-django/misitio.sock y Booting worker, sin errores. Desde el navegador todavía no puedes entrar (falta Nginx). Para Gunicorn con Ctrl+C.

  8. Crea el servicio de systemd

    sudo nano /etc/systemd/system/django-app.service
    [Unit]
Description=Gunicorn para el proyecto Django
After=network.target

[Service]
User=tuUsuario
Group=www-data
WorkingDirectory=/home/tuUsuario/mi-proyecto-django
ExecStart=/home/tuUsuario/mi-proyecto-django/venv/bin/gunicorn --access-logfile - --workers 3 --bind unix:/home/tuUsuario/mi-proyecto-django/misitio.sock --umask 007 misitio.wsgi:application

[Install]
WantedBy=multi-user.target

    El --umask 007 hace que el socket se cree con permisos para el grupo www-data, que es el de Nginx.

    sudo systemctl daemon-reload
sudo systemctl start django-app
sudo systemctl enable django-app
sudo systemctl status django-app
    Comprueba: el estado dice active (running) y existe el socket: ls -l ~/mi-proyecto-django/misitio.sock empieza por srwxrwx--- con el grupo www-data.

  9. Configura Nginx

    sudo nano /etc/nginx/sites-available/django-app
    server {
    listen 80;
    server_name IP-DE-TU-SERVIDOR;  # o tu dominio

    location = /favicon.ico { access_log off; log_not_found off; }

    location /static/ {
        root /home/tuUsuario/mi-proyecto-django;
    }

    location / {
        include proxy_params;
        proxy_pass http://unix:/home/tuUsuario/mi-proyecto-django/misitio.sock;
    }
}

    Nginx (que funciona con el usuario www-data) tiene que poder llegar hasta el socket y los estáticos, que están dentro de tu carpeta personal. Dale permiso para atravesarla (sin poder ver su contenido) y pon el proyecto en el grupo www-data:

    sudo chmod o+x /home/tuUsuario
sudo chown -R tuUsuario:www-data /home/tuUsuario/mi-proyecto-django

    Activa el sitio, desactiva los de las prácticas anteriores para que no respondan en su lugar, comprueba la configuración y reinicia Nginx:

    sudo ln -s /etc/nginx/sites-available/django-app /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default /etc/nginx/sites-enabled/todo-app /etc/nginx/sites-enabled/flask-blog
sudo nginx -t
sudo systemctl restart nginx
    Comprueba: http://IP-DE-TU-SERVIDOR (sin puerto) muestra ¡Hola Mundo desde Django en Debian! y http://IP-DE-TU-SERVIDOR/admin se ve con sus estilos (los sirve Nginx desde /static/).
    ¿Sale 502 Bad Gateway? Nginx no puede usar el socket. Mira el log (sudo tail /var/log/nginx/error.log): si dice Permission denied, revisa los permisos de tu carpeta personal y del proyecto; si dice No such file, el servicio django-app no está en marcha (sudo journalctl -u django-app -n 50).
    En un despliegue real, además, se pone DEBUG = False en settings.py y en ALLOWED_HOSTS solo tu dominio o tu IP.

    Captura: la web y el panel de administración funcionando por el puerto 80.

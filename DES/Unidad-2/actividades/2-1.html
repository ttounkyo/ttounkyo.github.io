Actividad 2.1. Petición HTTP con Telnet

Vas a «hablar» directamente con un servidor web: escribirás a mano una petición HTTP con Telnet y analizarás la respuesta. Es lo mismo que hace tu navegador cada vez que abres una página.

Lo que vas a practicar

  • Abrir una conexión TCP al puerto 80
  • La línea de inicio y la cabecera Host de una petición
  • La línea de estado, las cabeceras y el cuerpo de una respuesta
  • Los métodos GET y HEAD

Antes de empezar

  • Teoría: 2.5. Funcionamiento: un diálogo cliente-servidor y 4. Mensajes HTTP
  • Una terminal en tu ordenador o en tu servidor Debian.

Paso a paso

  1. Activa el cliente Telnet

    En casi todos los sistemas actuales Telnet no viene activado:

    • Windows: abre el Panel de control → Programas → Activar o desactivar las características de Windows, marca Cliente Telnet y pulsa Aceptar.
    • Debian y Ubuntu: instálalo con sudo apt install telnet.
    • macOS: ya no trae Telnet. Instálalo con Homebrew (brew install telnet) o usa nc example.com 80, que funciona igual para esta actividad.

  2. Conéctate al servidor web

    Abre una conexión con el servidor de example.com en el puerto de HTTP, el 80:

    telnet example.com 80

    Si la conexión funciona, verás Connected to example.com (o la pantalla se quedará en blanco, en Windows) esperando a que escribas.

    Ten la petición del paso siguiente preparada: si tardas mucho en escribir, el servidor cierra la conexión. En Windows, además, no se ve lo que escribes: escribe con cuidado.

  3. Envía una petición GET

    Escribe estas dos líneas exactamente así, pulsando Intro al final de cada una, y pulsa Intro otra vez al final. Esa línea en blanco le dice al servidor que la petición ha terminado.

    GET / HTTP/1.1
Host: example.com
    • GET / HTTP/1.1 es la línea de inicio:
      • GET es el método: quieres obtener un recurso.
      • / es la ruta del recurso: en este caso, la página principal.
      • HTTP/1.1 es la versión del protocolo.
    • Host: example.com es una cabecera obligatoria en HTTP/1.1: indica el dominio al que va la petición.

  4. Analiza la respuesta

    Nada más pulsar el segundo Intro, el servidor responde. La respuesta será parecida a esta (las cabeceras exactas cambian según el servidor y el día):

    HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256
Date: Tue, 21 Oct 2025 14:30:00 GMT
Last-Modified: Tue, 17 Oct 2023 07:18:26 GMT
ETag: "3147526947"
Connection: keep-alive

<!doctype html>
<html>
<head>
    <title>Example Domain</title>
    ... (resto del HTML de la página)
</html>

    Busca en tu respuesta sus tres partes y explícalas en tu entrega:

    • Línea de estado (HTTP/1.1 200 OK): la versión del protocolo, el código de estado (200, la petición ha ido bien) y el texto que lo describe (OK).
    • Cabeceras de la respuesta: datos sobre la respuesta. Por ejemplo, Content-Type (el tipo de contenido, aquí un HTML), Content-Length (el tamaño del cuerpo en bytes), Date (cuándo se generó) o Server (el software del servidor, si lo indica).
    • Cuerpo: después de una línea en blanco, el HTML de la página.

  5. Prueba el método HEAD

    Vuelve a conectarte y envía la misma petición con HEAD. El servidor solo devuelve las cabeceras, sin el cuerpo: sirve para saber si un recurso existe sin descargarlo.

    HEAD / HTTP/1.1
Host: example.com

    Compara la respuesta con la del paso anterior: ¿qué falta?

  6. Pide una página que no existe

    Conéctate otra vez y pide una ruta inventada, por ejemplo /no-existe.html. Anota el código de estado que te devuelve el servidor y explica qué significa.

    GET /no-existe.html HTTP/1.1
Host: example.com

    Hay más métodos: POST envía datos para crear un recurso (su petición lleva un cuerpo y es más larga de escribir a mano), PUT actualiza un recurso y DELETE lo borra. Los servidores públicos como este no te dejarán usarlos.

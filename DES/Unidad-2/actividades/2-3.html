Actividad 2.3. Servidores y arquitectura web

Seis ejercicios para afianzar la unidad: tres de investigación sobre HTTP y los servidores web, y tres prácticos en tu servidor: un stack LEMP, dos sitios con server blocks y el análisis de los logs.

Lo que vas a practicar

  • Versiones de HTTP y cabeceras de una petición real
  • Apache frente a Nginx
  • Stack LEMP: Nginx, MariaDB y PHP-FPM
  • Varios sitios con server blocks
  • Leer access.log y error.log

Antes de empezar

  • Teoría: 2. El protocolo HTTP, 4. Mensajes HTTP y 7. Servidores web: Apache y Nginx
  • Haber terminado la actividad 2.2: te servirá de guía para los ejercicios 4 a 6.
  • Tu servidor Debian (o un Ubuntu Server) con acceso por SSH.

Paso a paso

  1. Ejercicio 1. La evolución de HTTP

    Haz una tabla comparativa con las características de cada versión de HTTP y, sobre todo, con el problema principal que resolvió cada una:

    • HTTP/1.0: una conexión TCP nueva para cada recurso.
    • HTTP/1.1: lo poco eficiente que era abrir tantas conexiones.
    • HTTP/2: el bloqueo de cabeza de línea (Head-of-Line Blocking) a nivel de HTTP.
    • HTTP/3: el bloqueo de cabeza de línea a nivel de TCP.

  2. Ejercicio 2. Anatomía de una petición real

    Abre las herramientas de desarrollador del navegador (F12 o Ctrl+Mayús+I; en Mac, Cmd+Opción+I) y ve a la pestaña Red (Network).

    1. Visita una web compleja, como www.amazon.es o elpais.com.
    2. Selecciona la primera petición de la lista (normalmente, el documento HTML principal).
    3. Mira las cabeceras (Headers) de la petición y de la respuesta, y anota:
      • El método de la petición y el código de estado de la respuesta.
      • La cabecera de petición User-Agent. ¿Qué dice de tu sistema?
      • La cabecera de respuesta Content-Type. ¿Qué tipo de documento has recibido?
      • La cabecera de respuesta Server. ¿Puedes saber si usan Apache, Nginx u otro servidor? (Muchas webs la ocultan o ponen el nombre de su CDN).
      • Busca la petición de una imagen (JPG, PNG, WebP…) y compara su Content-Type con el del documento HTML.

  3. Ejercicio 3. Apache o Nginx

    Investiga y responde:

    1. ¿Qué son los archivos .htaccess de Apache y por qué son tan populares en los hostings compartidos? ¿Por qué Nginx decidió no tener nada parecido?
    2. Tienes que desplegar dos proyectos:
      • Proyecto A: un blog de WordPress con mucho tráfico y muchas imágenes.
      • Proyecto B: una intranet para una empresa de 10 personas con una aplicación PHP muy concreta que depende de varios módulos poco comunes de Apache.
      ¿Qué servidor web elegirías para cada uno (Apache, Nginx o una configuración híbrida)? Justifícalo con la arquitectura y las características de cada uno.

  4. Ejercicio 4. Instala un stack LEMP

    Antes de empezar, busca qué significa stack LEMP y explícalo en tu entrega. Documenta todos los pasos con capturas.

    1. Instala Nginx, MariaDB y PHP (con el paquete php-fpm y el conector de MySQL): 
      sudo apt update
sudo apt install nginx mariadb-server php-fpm php-mysql
    2. Comprueba que los tres servicios están en marcha (en Debian 13 la versión de PHP es la 8.4; si la tuya es otra, cambia el número): 
      systemctl status nginx mariadb php8.4-fpm
    3. Crea el archivo info.php en la carpeta web por defecto: 
      echo '<?php phpinfo(); ?>' | sudo tee /var/www/html/info.php
    4. Configura Nginx para que pase los archivos PHP a PHP-FPM. Abre el sitio por defecto con sudo nano /etc/nginx/sites-available/default y quita el # de las líneas del bloque location ~ \.php$, para que quede así: 
      location ~ \.php$ {
    include snippets/fastcgi-php.conf;
    fastcgi_pass unix:/run/php/php8.4-fpm.sock;
}

      Añade también index.php a la línea index del mismo archivo. Comprueba la configuración y recarga Nginx:

      sudo nginx -t
sudo systemctl reload nginx
    5. Abre en tu navegador http://IP_DEL_SERVIDOR/info.php. Tienes que ver la página de información de PHP.
    Cuando termines, borra info.php (sudo rm /var/www/html/info.php): muestra mucha información de tu servidor que no debe ser pública.

  5. Ejercicio 5. Dos sitios con server blocks

    Documenta todos los pasos con capturas. Puedes seguir la actividad 2.2 como guía.

    1. Crea dos carpetas para dos sitios: /var/www/sitio1 y /var/www/sitio2.
    2. En cada una, crea un index.html sencillo pero distinto (por ejemplo, «Bienvenido al sitio 1 de TUNOMBRE» y «Página principal del sitio 2 de TUNOMBRE»).
    3. Crea un server block para cada sitio en /etc/nginx/sites-available/, con los nombres sitio1.local y sitio2.local.
    4. Activa los dos sitios con sus enlaces simbólicos en /etc/nginx/sites-enabled/.
    5. En el archivo hosts de tu ordenador, haz que sitio1.local y sitio2.local apunten a la IP de tu servidor.
    6. Comprueba la configuración con sudo nginx -t, reinicia Nginx y abre los dos sitios en tu navegador con sus nombres.

  6. Ejercicio 6. Analiza los logs

    1. Abre sitio1.local. Después, intenta abrir una página que no existe, como sitio1.local/pagina-inventada.html.
    2. Conéctate al servidor y mira las últimas líneas de los logs de Nginx con tail: 
      sudo tail -n 20 /var/log/nginx/access.log
sudo tail -n 20 /var/log/nginx/error.log
    3. En access.log, localiza la línea de tu visita correcta (código 200) y la de la página que no existe (código 404).
    4. Mira también error.log. ¿Aparece el intento fallido? Explica lo que ves: con try_files … =404, Nginx responde 404 sin anotarlo como error, así que puede que no aparezca nada.
    5. Copia las líneas en tu entrega y explica qué información da cada parte (IP, fecha, petición, código de estado, tamaño, navegador…).

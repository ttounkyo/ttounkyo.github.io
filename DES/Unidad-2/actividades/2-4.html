Actividad 2.4. Transferencia de archivos con SFTP

Vas a publicar un sitio web nuevo subiendo sus archivos al servidor con SFTP desde FileZilla, en lugar de clonarlos con Git.

Lo que vas a practicar

  • Conectar con FileZilla por SFTP y con tu clave
  • Subir archivos al servidor
  • Resolver problemas de permisos
  • Repetir la configuración de un sitio en Nginx

Antes de empezar

  • Teoría: 1.2. Otras funciones de los servidores web y 7.5. Server blocks
  • Haber hecho la actividad 2.2.
  • FileZilla (el cliente) instalado en tu ordenador.
  • Los archivos de una web sencilla en tu ordenador (puede ser tuya o una plantilla).

Usar Git es una forma moderna de desplegar código, pero conviene conocer también los métodos tradicionales, como SFTP (SSH File Transfer Protocol). SFTP transfiere archivos de forma segura y cifrada usando SSH. No tienes que instalar ningún servidor FTP: SFTP funciona con el servidor OpenSSH que ya tienes instalado.

Paso a paso

FileZilla cambia los menús de sitio entre versiones y entre Windows y Mac. Si no encuentras una opción, busca una parecida.

  1. Prepara la carpeta del nuevo sitio

    En el servidor, crea la carpeta del sitio nuevo:

    sudo mkdir -p /var/www/actividad-24/html

  2. Añade tu clave a FileZilla

    Como entras al servidor con clave, FileZilla necesita tu clave privada. Ve a Edición → Opciones → Conexión → SFTP (en Mac, FileZilla → Preferencias) y pulsa Añadir archivo de clave. Elige tu clave privada: el archivo .ppk de PuTTY o el .pem / id_ed25519 de OpenSSH.

  3. Conéctate por SFTP

    En la barra de conexión rápida de FileZilla, escribe:

    • Servidor: sftp://IP_DEL_SERVIDOR
    • Nombre de usuario: tu usuario del servidor.
    • Puerto: déjalo vacío (se usa el 22) y pulsa Conexión rápida.

    La primera vez, FileZilla te avisa de que no conoce la clave del servidor, igual que PuTTY. Comprueba que la IP es la tuya y acepta.

  4. Sube los archivos de la web

    En el panel derecho, ve a /var/www/actividad-24/html. En el izquierdo, busca la carpeta de tu web y arrastra sus archivos al panel derecho.

    Error open for write: permission denied

    Es normal que te salga: la carpeta la creaste con sudo, así que es de root, y tú te conectas con tu usuario. Comprueba con qué usuario creaste la carpeta, sus permisos (ls -l /var/www/actividad-24) y con qué usuario te conectas en FileZilla. Intenta resolverlo antes de mirar la solución.

    Ver una solución

    Una forma de hacerlo: que la carpeta sea de tu usuario y del grupo www-data, con permisos para que Nginx pueda leerla. Cambia usuario por tu usuario:

    sudo chown -R usuario:www-data /var/www/actividad-24
sudo chmod -R 755 /var/www/actividad-24

    Vuelve a subir los archivos.

  5. Configura el sitio en Nginx

    Repite los pasos de la actividad 2.2 para el sitio nuevo: crea su server block en /etc/nginx/sites-available/actividad-24 con root /var/www/actividad-24/html y server_name actividad-24, actívalo con el enlace simbólico, comprueba con sudo nginx -t y recarga Nginx.

  6. Abre la web

    Añade actividad-24 con la IP de tu servidor al archivo hosts de tu ordenador y abre http://actividad-24 en el navegador.

Actividad 2.2. Instalar y configurar Nginx

Vas a instalar Nginx en tu servidor Debian, publicar en él una web de ejemplo con su propio server block y abrirla desde el navegador de tu ordenador con un nombre de dominio.

Lo que vas a practicar

  • Instalar un servicio con apt y comprobarlo con systemctl
  • La carpeta de la web en /var/www, su propietario y sus permisos
  • Server blocks: sites-available y sites-enabled
  • El archivo hosts de tu ordenador
  • Los logs de Nginx

Antes de empezar

  • Teoría: 7. Servidores web: Apache y Nginx, sobre todo 7.5. Server blocks
  • Tu servidor Debian de la unidad 1, y su IP. Conéctate a él por SSH.

Paso a paso

Las capturas son de Nginx 1.26.3 en Debian 13. En otras versiones los mensajes pueden cambiar un poco, pero los pasos y los archivos son los mismos. En las capturas el sitio se llama disenyo y su dominio es disenyo-creativo.com; tú usa tu propio nombre.

  1. Instala Nginx

    Actualiza la lista de paquetes e instala el servidor web:

    sudo apt update
sudo apt install nginx

  2. Comprueba que está en marcha

    systemctl status nginx

    Tiene que decir active (running). Fíjate también en los procesos: un master process y varios worker process, como explica la teoría. Sal con Q.

  3. Crea la carpeta de la web y descarga el sitio de ejemplo

    Los archivos de cada sitio se guardan en su propia carpeta dentro de /var/www. Crea la tuya (cambia nombre_web por el nombre de tu sitio):

    sudo mkdir -p /var/www/nombre_web/html

    Dentro, clona este repositorio con una web de ejemplo:

    sudo git clone https://github.com/cloudacademy/static-website-example.git /var/www/nombre_web/html

    Si sale sudo: git: command not found, instala Git con sudo apt install git y comprueba la versión con git --version.

  4. Ajusta el propietario y los permisos

    Haz que los archivos sean del usuario www-data, el usuario con el que trabaja Nginx, y ajusta los permisos para que pueda leerlos:

    sudo chown -R www-data:www-data /var/www/nombre_web/html
sudo chmod -R 755 /var/www/nombre_web

  5. Crea el server block del sitio

    Crea un archivo de configuración para tu sitio en sites-available. El archivo se llama como tu sitio, y dentro irá el server block: el bloque server { … } que le dice a Nginx cómo servirlo.

    sudo nano /etc/nginx/sites-available/nombre_web

    Pega este contenido y cambia nombre_web por tu sitio y tu dominio:

    server {
    listen 80;
    listen [::]:80;

    root /var/www/nombre_web/html;
    index index.html index.htm;

    server_name nombre_web www.nombre_web;

    location / {
        try_files $uri $uri/ =404;
    }
}

  6. Activa el sitio

    Activa el sitio con un enlace simbólico en sites-enabled, comprueba que la configuración no tiene errores y reinicia Nginx:

    sudo ln -s /etc/nginx/sites-available/nombre_web /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

    nginx -t tiene que responder syntax is ok y test is successful. Si da un error, te dice el archivo y la línea: corrígelo antes de reiniciar.

  7. Añade el dominio al archivo hosts de tu ordenador

    Todavía no tienes un servidor DNS, así que tienes que decirle a tu ordenador (el anfitrión, no el servidor) qué IP tiene tu dominio. Se hace en el archivo hosts:

    • Linux o macOS: sudo nano /etc/hosts
    • Windows: abre el Bloc de notas como administrador y, desde él, el archivo C:\Windows\System32\drivers\etc\hosts.

    Añade al final una línea por cada nombre, con la IP de tu servidor:

    # IP de tu servidor Debian (compruébala con ip a)
192.168.X.X   nombre_web
192.168.X.X   www.nombre_web
    Con el adaptador puente, la IP del servidor depende de la red: no será la misma en clase que en casa, y puede cambiar de un día para otro. Si la web deja de abrirse, comprueba la IP con ip a y corrígela en hosts.

  8. Abre la web en el navegador

    En el navegador de tu ordenador, entra en http://nombre_web. Tienes que ver la web del repositorio que has clonado.

  9. Revisa los logs del servidor

    Nginx anota cada petición en sus archivos de registro:

    • /var/log/nginx/access.log: todas las peticiones que recibe.
    • /var/log/nginx/error.log: los errores que encuentra.
    sudo tail /var/log/nginx/access.log

    Busca las líneas de tus visitas: verás la IP de tu ordenador, la fecha, la petición (por ejemplo, GET /assets/css/main.css) y el código de estado.

    Si no ves tus visitas, puede que el navegador haya guardado la página en caché. Ábrela en una ventana privada o de incógnito para forzar una petición nueva.

  10. Responde a las preguntas

    Contesta en tu entrega, con tus palabras. Si quieres, pruébalo en tu servidor y deshazlo después:

    1. ¿Qué pasa si no haces el enlace simbólico de tu sitio entre sites-available y sites-enabled?
    2. ¿Qué pasa si no das el propietario y los permisos adecuados (chown y chmod) a la carpeta /var/www/nombre_web?

Comprueba antes de entregar
